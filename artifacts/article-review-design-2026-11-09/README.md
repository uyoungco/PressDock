# PressDock 批量审核视觉设计稿

这是原始视觉与交互提案，使用明确标识的演示数据，不连接 CMS。现已按用户确认落地到业务组件；用户随后取消拒绝原因，因此第三张原因表单仅保留为历史设计，实际单条与批量拒绝均直接进入二次确认。实施与验证见[实施记录](../../docs/cms-article-review-implementation-2026-11-09.md)。以下内容描述原设计稿。

## 查看

- `mobile-design.png`：Android 选择稿件、批量核对、填写拒绝原因三种状态
- `desktop-design.png`：桌面工具栏与选中行的对应样式
- `design-board.png`：完整设计板
- `design.html`：可直接打开的独立设计板；地址加 `?view=prototype` 可体验手机布局
- `design-board.pdf`：矢量排版导出中间稿
- `browser-checks.json`：ego-browser 的尺寸与交互检查记录

交互稿支持单选、当前页全选、清空、进入批量审核、同意二次确认、拒绝原因去空白必填。确认只展示“设计演示：未执行审核”，不会模拟真实审核成功。筛选、编辑、单篇审核等背景入口仅用于展示原有页面上下文，不连接项目业务服务。

## 问题审视

本次属于局部打磨，沿用现有校样蓝与字体。

| 位置           | 问题                                           | 处理                                                 |
| -------------- | ---------------------------------------------- | ---------------------------------------------------- |
| 手机选择工具栏 | 全选、数量、清空、主按钮挤在同一行             | 全选与清空留在列表顶部，数量与审核操作成组固定在底部 |
| 批量审核按钮   | 蓝色块与周围内容缺少分组，缺少明确的选择上下文 | 统一为 48px 高、8px 圆角，放在选择摘要右侧           |
| 已选稿件       | 主要依靠一个勾选图标反馈                       | 增加浅蓝底、左侧 2px 细线，与勾选颜色联动            |
| 批量稿件清单   | 编号和标题混在普通文本中，扫描困难             | 序号固定窄列，标题与元信息分层，对齐行距             |
| 拒绝表单       | 原因与稿件清单之间的层次不足                   | 独立分组，原因说明靠近输入框，仅在拒绝提交使用语义红 |

## 五行方向

- 产品：为新闻编辑提供可核对当前页稿件的批量审核
- 气质：克制、准确、有条理
- 场景：编辑台上的稿件清单与蓝色批注
- 重点：选择摘要、选中稿件、批量确认区形成连续反馈
- 识别细节：固定稿件编号列与选中稿件的蓝色批注线

## 九轮调整

| 顺序 | 调整                                                                         |
| ---- | ---------------------------------------------------------------------------- |
| 间距 | 页面边距 16px，分组间距 24px，主操作 48px 高，手机方框 20px、触控区 44px     |
| 颜色 | 沿用 `#2457d6`；选中底 `#f2f6fe`；背景、分隔线和元信息采用中性灰             |
| 图标 | 使用项目已有 Lucide，默认 18px、1.5px 描边；勾选按控件缩小                   |
| 文案 | “全选本页”“已选 2 篇”“批量审核”；拒绝原因说明同批共用，不声称发布成功        |
| 字体 | 保留现有界面无衬线体系，正文 14–15px、辅助文字 12px，数量用等宽数字          |
| 布局 | 手机选择与主操作分组；批量核对使用底部面板保留列表上下文；桌面保留表格工具栏 |
| 细节 | 按钮 8px 圆角，批量面板顶部 20px 圆角，安静细边线，明确焦点样式              |
| 视觉 | 内容本身承担重点：标题、编号、选择摘要；保留配图入口，不增加装饰图片         |
| 动效 | 仅保留 160ms 颜色反馈，无循环、弹跳或布局尺寸动画                            |

## 落地边界

本次视觉提案将 Android **批量**核对与拒绝原因改为底部面板；单条审核仍保留原计划的全屏正文预览。面板稿件区域需内部滚动，操作区固定，并适配安全区、软键盘、返回与请求锁。稿件很多时保留内部滚动与总数量，不能把全部内容挤进首屏。

同意仍需再次确认，拒绝原因不新增字数上限，选择仍只限当前页；草稿阻挡、认证、权限、逐篇结果和禁止自动重试规则全部沿用现有实现。正式落地需使用真实组件、焦点管理、无障碍弹层与请求期间禁用态；独立设计 HTML 不是可替代业务组件的完整实现。

桌面设计板仅突出与批量审核有关的稿件、作者、时间及操作列；落地仍保留当前项目的配图、分发记录、筛选与列配置能力，不以设计板简化背景列为删功能依据。

## 检查

- 使用 ego-browser 加载本机独立 HTML
- 360px 手机宽度：无横向溢出，主按钮在视口内，20px 方框与 44px 触控区
- 清空后主按钮禁用；全选当前页选择 4 条演示稿件
- 同意进入二次确认；拒绝原因去空白后必填
- 仅反馈设计演示，没有 CMS 网络或写请求
- 截图接口在最小空白页也出现超时，改用同一 ego 页面 `Page.printToPDF`，经 Poppler 转为 PNG；两轮视觉审校
