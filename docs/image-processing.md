# 图片处理组件

## 使用方式

```tsx
import { ImageProcessor } from "@/features/images";

<ImageProcessor
  image={file}
  preset={{
    maxBytes: 100 * 1024,
    size: { width: 750, height: 750 },
    format: "jpeg",
  }}
  onConfirm={(result) => {
    // result.file 是实际编码的 File，可交给业务服务保存或由后续上传流程使用。
    console.log(result.width, result.height, result.format, result.byteSize);
  }}
  onCancel={close}
/>;
```

`image` 必须是 File 或 Blob。`preset` 的三个字段均可省略，分别锁定，重置不能解除锁定。尺寸锁定仅限制输出宽高，仍可移动和缩放相同比例的裁剪框；未指定输出宽高时默认不裁剪、不改变原始像素尺寸。开启自由裁剪后保留选区像素尺寸；指定宽高后按该比例裁剪并精确输出。允许放大，界面提示清晰度可能下降。预览查看倍率不参与导出计算。

`onConfirm` 返回 `{ file, width, height, format, byteSize }`，只在实际编码、格式、尺寸和体积校验通过后可用。修改图片、预设或处理参数后旧结果立即失效。取消组件本身不写文件。图片页面通过业务服务另存为，默认建议名为 `原文件名-processed.扩展名`，用户取消系统对话框不会提示成功。

## 编码与边界

| 项目         | 约定                                                                                                                                           |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 格式         | 静态 JPEG、PNG、WebP；按签名识别并核对非空 MIME；拒绝 APNG、动画 WebP、GIF、损坏文件                                                           |
| 资源         | 输入及结果最多 20 MiB；单边最多 16384；总像素最多 2400 万；解码器分配预算 256 MiB；同时编码 1 个任务                                           |
| 方向         | 解码时应用 EXIF 方向一次，预览与裁剪均基于校正后的尺寸；输出去除原 EXIF                                                                        |
| 颜色         | Little CMS 将 RGB / 灰度 ICC 转为 sRGB；无 ICC 按 sRGB 处理，不主动调色；不支持 CMYK / 其他 ICC 色彩空间；输出统一 8 位                        |
| 透明度       | PNG / WebP 保留 Alpha；JPG 合成白底；尺寸调整前预乘 Alpha，减少透明边缘杂色                                                                    |
| JPG / WebP   | 默认优先质量 90，可选 60–100；超过体积上限则在 60 至优先质量间搜索；每轮从同一份像素编码                                                       |
| PNG          | 先 RGBA 无损编码，再 oxipng；必要时 exoquant 256 色 Floyd–Steinberg 减色，不缩小尺寸                                                           |
| PNG 质量门槛 | 对全图黑底 / 白底合成逐像素检查：RGB RMSE ≤ 3，单通道平均偏差 ≤ 0.75，逐像素 RGB 通道偏差 ≤ 16、Alpha 偏差 ≤ 2；未通过即保留无损路径并报告超限 |
| 保存         | Rust 系统另存为；扩展名与实际格式一致；不覆盖任何已有文件；写入失败或检测到取消时清理新建文件                                                  |

PNG 门槛是保守的数值检查，不能代替所有内容的人工观感判断。照片、文字截图、渐变和透明边缘仍应检查实际结果。JPEG / WebP 质量值对应各自编码器，不代表跨格式统一的视觉评分。极小上限不保证可达，错误展示当前候选的实际字节数和上限，用户不能确认失败结果。

exoquant 0.2 的默认内部颜色逆变换会在逆 Gamma 之后才消除 Alpha 权重，导致调色板亮度偏差。这里保留它的量化器和抖动器，修正内部逆变换的顺序并采用对称取整；RGB / Alpha 往返测试和可达体积的减色测试覆盖此行为。这只修正量化过程的颜色计算，不对原图主动调色。

输出不保留原始 EXIF、其他元数据和宽色域配置；颜色转换目标为 sRGB，超出 sRGB 色域的颜色可能有不可避免的变化。高位深输入统一到 8 位，CMYK 或不支持的配置明确拒绝，不会静默忽略 ICC。原始文件始终独立保留。

## IPC 与生命周期

- `image_inspect({ jobId, input })`：检查内容、资源、方向、ICC，返回源尺寸 / 格式 / 实际字节及最多 1600 像素的规范化 PNG 预览。
- `image_process({ request })`：`input` 为 `{ dataBase64, mimeType }`；`crop` 为 0–1 归一化选区；可带 `size`、`maxBytes`，必须带 `format` 与 `quality`。返回实际编码字节及元信息。
- `image_cancel({ jobId })`：设置取消标记。无需有效会话，以便会话失效后仍可清理工作。
- `image_export({ jobId, input, format, fileName })`：复核图片后打开系统另存为，仅实际写入成功返回 `saved: true`。

检查、处理、导出均验证工作区会话，并在异步结果返回前复核会话版本。任务使用 UUID，取消、卸载、参数变化和会话失效不会回填旧结果。原生库内部的单次解码 / 编码调用不能在任意指令处抢占，取消检查发生在调用前后及逐行处理边界；期间保持并发资源限制，完成后丢弃结果并清理登记。

图片处理本身提供四个明确的图片命令。组件不调用 invoke，所有 IPC 由 Zod 校验。独立图片页只处理并另存为，素材表单在用户确认结果后通过现有 CMS 上传业务服务上传。

## 子渠道预设与素材表单

设置页按渠道、子渠道分别编辑 TitlePic 和 TitlePic2 的 `ImageProcessorPreset`，每项可省略。输出宽高必须成对配置，体积使用 KiB 输入并转为字节；格式为单选 JPG、PNG、WebP。固定尺寸、2400 万总像素及 20 MiB 体积边界与处理器一致。清空某个字段后保存会删除其规则，两个字段在同一事务内更新。

`list_channel_image_presets()` 和 `save_channel_image_presets({ request })` 通过独立类型化 IPC、Rust 命令与 SQLx 访问 `channel_image_presets` 表，主键为渠道、子渠道、图片字段。配置仅包含规则，本机工作区共用，默认无规则；不保存业务图片、正文或密钥。设置页合并 CMS 渠道列表与已保存的历史配置，历史规则仍可编辑和清空。

素材表单以触发时的渠道、子渠道和图片字段读取最新预设，再将 File 与预设传入现有 `ImageProcessor`。未匹配时传空预设；读取失败只允许重试或取消，不进入无规则处理。输入不要求与输出格式一致，仍只支持处理器可解码的静态 JPG、PNG、WebP。

粘贴监听仅绑定在两个图片地址输入框的 `onPaste` 上，并检查实际焦点；遇到图片只取第一张并阻止默认粘贴，纯文本交由输入框正常处理。没有全局剪贴板监听、轮询或自动读取权限请求。

图片弹框独立于素材表单的 HTML form，显示目标字段与渠道上下文。读取、处理及上传全过程占用图片操作锁，阻止保存素材、更改渠道及重复选图。确认前不上传；确认后业务服务再次核对结果尺寸、格式、MIME 与实际字节数，仅上传结果 File。失败保留结果，用户可手动重试。成功后只回填对应地址，不自动提交素材。

取消、Escape 仅关闭图片弹框并恢复对应输入框焦点。上传时可取消回填，但不能撤销已发送的网络写请求。关闭、卸载与会话失效会取消本地处理并通过操作版本丢弃旧回调。手填图片地址及更改渠道不自动触发处理。

## 验收方式

执行 README 全部检查。单元测试覆盖三格式真实签名 / 解码、尺寸保持、750×750、体积可达 / 不可达、透明底、透明边缘、EXIF 旋转、RGB ICC 色卡、非法 MIME / 损坏内容 / 资源上限、动画拒绝、任务取消、预设锁定、旧结果失效及导出成功提示。

隔离交互验收：

```powershell
npm run image:qa
# 浏览器打开 http://127.0.0.1:1431/image-qa
```

工具编译并调用 Rust 测试编码器，使用正式组件与业务服务，页面明确显示“隔离验收”。测试固定宽高、单字段 / 全字段预设、拖动 / 键盘、倍率和结果确认，不连接 CMS，不提供系统另存为。退出终端后验收服务停止，临时数据位于忽略目录 `.tools/image-qa`。真实桌面的系统保存对话框须在桌面登录后单独验收。

生成代表性编码样本与 CSV 记录：

```powershell
. .\scripts\use-local-rust.ps1
$env:PRESSDOCK_IMAGE_QA_DIR = "$PWD/src-tauri/target/image-qa/samples"
# 可选：使用本地照片作为第 5 类样本，不会修改该照片。
$env:PRESSDOCK_IMAGE_QA_PHOTO = 'C:/Windows/Web/Wallpaper/Spotlight/img50.jpg'
cargo test --manifest-path src-tauri/Cargo.toml --locked generate_visual_samples_when_requested -- --nocapture
Remove-Item Env:PRESSDOCK_IMAGE_QA_DIR
Remove-Item Env:PRESSDOCK_IMAGE_QA_PHOTO -ErrorAction SilentlyContinue
```
