| 项目         | 决策                                                               |

| 启动读取失败 | 使用上次缓存并提示；首次没有缓存时要求重试                         |

## 同步范围

| 全局共享                                          | 仅本机保存                                       |
| ------------------------------------------------- | ------------------------------------------------ |
| AI 提供商地址、协议、兼容参数及 API 密钥          | CMS 登录令牌及来源站点会话                       |

| 渠道图片尺寸、格式和体积预设                      | 历史保留天数                                     |

采集任务、原文、编辑草稿和业务列表运行缓存不属于配置同步数据。共享设置的新增、修改、删除及密钥清除均需要上报。

## 已确定的技术方向

采用 Workers + D1 + 本机缓存。客户端沿用 React → 业务服务 → 类型化 IPC → Rust 分层；Rust 经 HTTPS 访问 Worker，本地数据库仍由 SQLx 管理。

D1 保存全局配置与版本信息；不增加按用户划分的配置所有者。鉴权与配置归属分别处理：即使配置共享，每次云端读写仍须验证当前登录身份。不能只接受客户端自报的用户 ID，也不能把 Cloudflare 数据库管理令牌放进软件。

步骤 1 已验证 Worker 可通过现有 CMS 的真实 `CurrentUser` 接口校验身份，后续业务接口沿用该链路。操作者信息可以用于变更记录，不参与配置隔离。

启动读取在登录或会话恢复成功后执行，每个进程只完成一次成功的云端初始化；失败允许用户重试。业务功能使用完整、已校验的配置快照；下载失败不能用空配置覆盖缓存。换号或退出时，旧身份发起的网络响应不得继续落地，待上报操作也不得绕过重新鉴权。

运行中不轮询，打开设置页、切换业务页面、窗口聚焦、后台返回前台和网络恢复均不触发整份配置读取。网络恢复只补传待传操作。运行中退出再登录也不额外读取已完成初始化的全局配置；如果启动读取尚未完成，可在有效登录状态下继续完成初始化。

### 冷启动流程

1. 完成已有 CMS 登录或会话恢复；身份无效时保留在登录流程，不向未登录界面提供云端密钥。
2. 请求最新全局配置与密钥，校验配置版本、字段和引用关系。
3. 将非秘密配置更新到本地 SQLite，密钥更新到安全凭据库。整份配置成功落地后再标记初始化完成；任一步失败保留原有效副本，避免混合新旧密钥状态。
4. 若有未上报修改，在云端快照上重新应用这些修改作为本地视图，并按序补传；不上传本机整份旧缓存。
5. 云端不可用时使用有效缓存并提示；没有有效缓存时显示重试入口，暂不进入依赖配置的工作区。待传操作本身不视为完整有效缓存。

### 首次初始化

当前电脑作为唯一指定的初始数据来源，由 Rust 读取现有提供商、模型、模板、图片预设和共享采集规则，再从本机安全凭据库读取对应 AI 密钥，生成一次性初始化请求。密钥读取失败时明确提示并保留重试能力，不静默跳过。

云端只允许在未初始化时原子创建全局配置。请求超时可使用同一幂等 ID 重试；云端已存在配置时返回已有状态，不能用本机旧数据覆盖。其他设备不自动把自己的历史配置作为初始配置上传；云端尚未就绪时显示等待初始化或重试。

以后每次冷启动都读取云端版本，不重复导入旧设置。开发环境和生产环境使用不同数据库及加密主密钥。

### AI 密钥

密钥由 Rust 与 Worker 之间传输；读取后放入平台安全凭据库，常规前端配置仍只返回本机密钥是否可用。D1 保存应用层加密后的密文，加密主密钥放在 Worker 的服务端 Secret 中，与数据库分开。

加密格式应携带版本、密钥版本和随机 nonce，并绑定提供商标识等必要上下文，支持后续轮换。静态配置读取、操作日志、错误信息和审计记录均不得暴露明文密钥。

离线补传时，本地队列只保存密钥引用和操作信息；待传密钥的稳定副本由平台安全存储管理，避免重试时误读成之后修改的新值。本地 SQLite 和 localStorage 不保存密钥明文。凭据库和 SQLite 的跨存储更新应沿用先安全保存、失败回滚或补偿的方式。

### 修改上报与补传

沿用现有设置的保存动作：模型、模板和图片预设经表单保存后上报；采集规则沿用 500 毫秒防抖自动保存。输入中的未提交草稿不直接上传，本机偏好不产生云端请求。

业务服务将一次操作表达为有限的字段修改、创建或删除，不上传本机完整旧快照。例如手机只修改图片格式时，上报图片格式的变化，不同时回写它上次启动时读取的模型参数。

非秘密配置的本机保存和待传操作在同一个 SQLite 事务内提交。Rust 按设备内操作顺序上报；同一操作的重试沿用幂等 ID，服务端只应用一次。请求超时后即使重发，也不能再次覆盖之后已提交的新值。

Worker 原子合并允许修改的字段并递增服务端 revision。不同设备修改不同字段可以同时保留，同一字段取服务端最后接受的有效操作；不使用设备时钟排序，也不显示人工冲突选择框。删除和被引用关系仍须校验，不能把无法应用的操作当作成功。

网络错误、限流和临时服务故障保留队列，采用有上限的退避重试；网络恢复或下次启动也触发补传。鉴权失效时暂停，登录后恢复；数据校验或引用失败时显示具体原因，等待用户处理，不能无限自动重试。

启动有待传修改时，先接收云端快照，再把待传操作覆盖回本地视图，随后按序补传。读取失败但存在有效缓存时，继续使用缓存和待传修改。离线较久的同字段修改补传后可能覆盖其他设备之前保存的值，这是已选择的“服务端最后收到为准”规则。

保存返回只确认该操作及其版本，不触发运行期整份配置拉取；因此“修改已上报”不代表本机已读取其他设备所有最新修改。运行中其他设备的变化在下次约定的读取时机生效。

### 配置依赖

模型、提供商、模板、图片预设和采集规则之间的引用需要服务端再次校验。被共享模板或规则引用的模型不能直接删除；需要先解除引用或在同一次有效操作中调整依赖。

同步只改变后续使用的配置；已经入队或运行中的任务继续使用其配置快照，不重新触发 AI 或 CMS 提交。本地应用删除时保留未完成任务需要的非秘密配置历史；若对应密钥已清除或撤销，则显示明确错误，不能自动改用其他模型或重发请求。

### 状态展示

界面应分别表达启动读取中、正在使用缓存、本机已保存且待上报、上报中、修改已上报和上报失败。收到本地保存成功与收到云端确认是不同事件，不用“全局配置已完全同步”描述单次上报成功。

## 验收方向

- 两个不同账号读取到同一份全局配置，均可修改；未登录者不能读取配置或密钥。
- 每次冷启动完成一次云端配置初始化，不因组件重复挂载产生额外启动请求；前后台切换、打开设置页、运行中换号和网络恢复不额外拉取配置。
- 启动读取失败时正确使用缓存；首次无缓存时可重试。
- 新设备读取共享配置及 AI 密钥后可实际使用，界面与日志不暴露明文。
- 上报失败后本机继续生效并可在重启后补传；重复请求不会再次覆盖后续配置。
- 两端修改不同项均保留，同一项以服务端最后收到的有效保存为准；旧缓存不会覆盖无关字段。
- 首次只导入当前电脑的已有配置和密钥，其他设备历史配置不会覆盖已初始化云端。
- 远端配置不覆盖尚未提交的编辑草稿，不改变已存在任务的快照。
- 本轮根据用户确认在真实 Windows 设备上完成剩余验收；已有 Android 结果保留，macOS 实测为本轮范围外。
