## 目标与完成定义

交付一套全局共享配置：所有已登录用户均可读写；每次冷启动读取一次；修改先保存本机并自动上报；失败持久补传；只更新修改项；同字段以服务端最后接受的有效操作为准；AI 密钥在服务端加密保存并下发到客户端安全凭据库。

主题、历史保留天数、采集方式、CDP 配置、开发者模式和布局偏好保留本机。业务正文、草稿、采集任务和 CMS 会话不进入配置同步。

每个阶段完成后记录实际版本、测试命令、预期与实际结果、脱敏证据及未解决问题。进入下一阶段前，应通过本阶段的必验项；仅有代码、Mock 测试或截图不代表真实集成验收完成。

## 第一步：验证连接与身份校验

目的：确认已选架构能使用现有真实登录体系，不增加一套未经验证的账号系统。

开发内容：创建隔离的开发 Worker 和开发 D1；验证 Worker 可访问 D1、可请求固定 CMS 主机已有的 `GET /api/Account/CurrentUser`；将身份校验放到服务端。凭据仅经 Rust 和 Worker 传递，不交给常规前端配置读取接口。

交付物：最小可运行服务、环境配置示例、真实链路验证记录。示例文件不包含真实令牌、AI 密钥或加密主密钥；操作记录仅保留必要的状态和脱敏结果。

| 用例  | 操作                                        | 通过标准                                                                |
| ----- | ------------------------------------------- | ----------------------------------------------------------------------- |
| S1-01 | 使用实际有效的 CMS 会话访问受保护的验证入口 | Worker 经真实 CMS 接口确认身份并返回成功；不是仅解析客户端自报的用户 ID |
| S1-02 | 使用缺失/篡改凭据请求，并注入已失效响应     | 均不能执行受保护的 D1 读写，不返回配置或密钥                            |
| S1-03 | 将 CMS 校验请求模拟为超时或服务不可用       | 返回可识别的临时失败，绝不降级为授权成功                                |
| S1-04 | 经实际部署的 Worker 执行 D1 验证查询        | 正常返回；开发数据与生产数据分开                                        |
| S1-05 | 检查本轮请求日志、错误输出和前端可见状态    | 无令牌和密钥明文，无将凭据交给前端展示的接口                            |

阶段完成标准：以上五项全部通过，保留真实 Worker→CMS 和 Worker→D1 的脱敏证据。真实 CMS 验证尚未打通时，本阶段保持未通过；可以继续准备协议，但不能宣称鉴权已经具备或开始生产导入。

## 第二步：确定配置协议与数据模型

已交付：[协议 v1](settings-sync/protocol-v1.md)、字段映射、TypeScript/Rust 验证器、80 组共享样例及 D1/本地迁移草案。逐项结果见[步骤 2 验收](cloudflare-d1-settings-step2-qa-2026-11-07.md)。

开发内容：为全局配置定义 `schemaVersion`、服务端 `revision`、字段范围和引用关系；为修改定义稳定 `operationId`、设备内顺序、创建/更新/删除/清除密钥语义。操作者可记录在变更元数据中，不作为配置所有者。

同步粒度以真正改变的字段为准。例如只改模型显示名称，就不回写表单中仍显示的旧输出上限；模板正文作为一个文本字段更新。不同字段可以合并，同一字段按服务端有效提交顺序决定。非法引用不适用“最后写入获胜”，应明确拒绝。

交付物：配置字段对照表、客户端/服务端协议定义与有效/无效样例、错误码表、D1 和本地迁移设计。建议新增的 Worker 代码放在独立目录并使用 npm；保留现有锁文件。

| 用例  | 操作                                           | 通过标准                                                                     |
| ----- | ---------------------------------------------- | ---------------------------------------------------------------------------- |
| S2-01 | 对照现有模型、模板、图片预设及采集规则逐项检查 | 所有共享字段均有映射，所有本机字段均被排除，密钥不混入普通前端快照           |
| S2-02 | 客户端和服务端验证同一组协议样例               | 有效输入均接受；未知修改路径、越界值、无效引用和不支持的版本均有明确拒绝方式 |
| S2-03 | 检查更新、删除、清除密钥和重复请求约定         | 每种操作均能区分“未修改”“置空”“删除”，重试不会被当成新操作                   |
| S2-04 | 用大模板和多预设数据检查大小限制               | 按 UTF-8 实际字节计量；超限明确失败且不截断、不部分写入                      |

阶段完成标准：共享字段清单覆盖率 100%，所有协议样例结果一致，后续阶段不再依赖未定义的保存或删除语义。

## 第三步：实现云端配置服务

开发内容：实现受保护的全局读取、未初始化状态、一次性初始化、字段级修改、服务端校验、幂等记录及错误返回。D1 配置没有账号所有者；所有写入以原子方式合并并产生服务端版本。

AI 密钥采用应用层认证加密，D1 只存密文及版本信息，主密钥保存在 Worker Secret。授权下载由 Worker 解密后通过 HTTPS 交给 Rust；幂等记录与错误信息不得附带密钥明文。

交付物：Worker 实现、D1 迁移、自动化测试、独立开发环境部署及脱敏接口验证记录。生产环境初始化安排在后续阶段。

| 用例  | 操作                                                     | 通过标准                                                                |
| ----- | -------------------------------------------------------- | ----------------------------------------------------------------------- |
| S3-01 | 现有有效账号读取和修改配置，另用未登录请求访问           | 现有账号可读写全局配置；未登录请求被拒绝；跨账号实测为本轮范围外        |
| S3-02 | 同一初始化请求提交三次，再用不同内容尝试初始化           | 全局配置只创建一次；后续尝试不覆盖已有数据                              |
| S3-03 | 同一快照基础上，两端同时修改不同字段                     | 两项均保留；同一模型的不同字段也不会互相回写旧值                        |
| S3-04 | 两端依次修改同一字段                                     | 最后被服务端接受的有效保存生效，设备时钟不参与判断                      |
| S3-05 | A 操作已落库但响应丢失，B 操作修改同一字段成功后再重试 A | A 返回原有处理结果，不再次写入，不覆盖 B，revision 不因重复请求增加     |
| S3-06 | 删除仍被模板引用的模型，或提交非法参数                   | 原子拒绝，已有配置及版本保持不变                                        |
| S3-07 | 保存、下载、替换和清除一份专用测试密钥                   | 授权客户端取得正确结果；D1 导出和日志不包含该明文；篡改密文不能成功解密 |
| S3-08 | 查询或写入过程中注入 D1 故障                             | 不返回虚假成功，不留下只修改了一部分字段的有效结果                      |

阶段完成标准：全部用例通过；S3-03、S3-04、S3-05 每组连续执行 20 轮，无丢失修改或重复应用。至少一次使用实际开发 D1 验证，不能全部依靠内存替身。

## 第四步：实现 Rust 本地快照与持久队列

开发内容：增加本地配置版本、有效快照、待传操作及状态存储；提供类型化 IPC。非秘密配置的本机修改与入队在同一事务完成；配置密钥保存在平台凭据库，整个待传请求加密后存入 SQLite，对应随机解密密钥保存在平台凭据库，非秘密队列索引不包含请求明文。

下载快照采用准备和切换有效版本的方式，处理 SQLite 与凭据库无法共用一个事务的情况。迁移及同步不修改原文或草稿正文；0011 迁移仅为旧采集任务补充执行配置及安全凭据引用快照，保留原任务业务字段。

交付物：SQLx 迁移、Rust 配置与队列服务、凭据保存及补偿逻辑、IPC 类型与存储故障测试。

| 用例  | 操作                                              | 通过标准                                                         |
| ----- | ------------------------------------------------- | ---------------------------------------------------------------- |
| S4-01 | 在已有数据库上升级并重新打开应用                  | 配置、原文、草稿、任务均保留；重复迁移不重复导入、不覆盖既有数据 |
| S4-02 | 修改配置后在上报前结束进程，再重新启动            | 待传操作、顺序和 operationId 保留，修改不丢失                    |
| S4-03 | 在本机配置保存和入队之间注入 SQLite 写入失败      | 事务整体失败，不出现“配置已变但没有待传记录”                     |
| S4-04 | 下载新快照时让凭据库或 SQLite 写入失败            | 原有效配置仍可用，不切换到不完整的新版本；失败可重试             |
| S4-05 | 连续修改同一密钥，保留两个待传操作并重启          | 每个操作引用自己的稳定版本；重试旧操作不误读最新密钥             |
| S4-06 | 检查 SQLite、localStorage、IPC 普通读取结果及日志 | 无密钥明文；普通配置接口仅返回密钥是否可用                       |

阶段完成标准：存储故障测试通过，缓存与队列实际跨进程保留，并在当前 Windows 环境验证真实安全凭据库。其他平台的原生验证在第八步补齐。

## 第五步：接入冷启动读取

开发内容：在登录或会话恢复成功后执行一次全局初始化；只在得到完整有效结果后启用云端快照。读取失败时使用有效缓存，无缓存时提供重试。启动有待传操作时，将其重新应用到刚读取的云端快照再补传。

交付物：应用启动流程、读取次数控制、缓存回退与重试界面、身份变化时的取消处理及请求计数证据。

| 用例  | 操作                                                           | 通过标准                                                             |
| ----- | -------------------------------------------------------------- | -------------------------------------------------------------------- |
| S5-01 | 云端修改一个标识字段，完全退出后重新启动并登录                 | 读取并使用新值；正常路径配置快照成功读取恰好一次                     |
| S5-02 | 反复切页面、打开设置、聚焦窗口、后台返回、断网恢复及运行中换号 | 初始化成功后新增整份配置读取次数为 0；允许独立鉴权请求与待传操作上报 |
| S5-03 | 有有效缓存时让云端超时                                         | 使用缓存进入工作区并提示；不以空配置或默认值覆盖缓存                 |
| S5-04 | 清空测试安装的缓存后让云端失败，再恢复服务并点击重试           | 首次失败停留在重试界面；重试成功后进入工作区且不重复初始化           |
| S5-05 | 保留一个待传模型修改，同时在云端修改图片预设后冷启动           | 本机看到待传模型修改和云端新图片预设；补传只包含模型变化             |
| S5-06 | 初始化响应返回前退出或切换登录身份                             | 旧响应被丢弃；有效登录可完成尚未成功的初始化                         |

阶段完成标准：每个触发场景的抓包或计数结果符合上表，不依靠“看起来没有刷新”判断读取次数。

## 第六步：接入修改自动上报与补传

开发内容：模型、模板、图片预设沿用表单保存；采集规则沿用 500 毫秒防抖保存。保存后本机立即生效并自动发送修改项；新增、删除、替换或清除密钥采用同一待传机制。本机偏好不发送同步请求。

增加“正在使用缓存”“本机已保存，待上报”“上报中”“修改已上报”“上报失败”等状态。网络与临时服务故障退避重试，登录失效暂停；永久校验失败保留错误等待修正。

交付物：现有业务服务接入、差量生成、重试调度、设置状态展示及端到端验证记录。页面仍通过业务服务和类型化 IPC 操作，不直接调用云 API。

| 用例  | 操作                                                                | 通过标准                                                                 |
| ----- | ------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| S6-01 | 逐类新增、编辑、删除共享设置，另做密钥替换与清除                    | 本机生效并生成正确修改项；合法操作最终反映到云端；非法依赖明确失败       |
| S6-02 | 修改一个表单字段，其余字段使用本机旧值                              | 请求只包含改变的字段，云端其他设备已修改的无关字段保持不变               |
| S6-03 | 编辑但不提交模板，连续快速切换采集开关                              | 未提交模板不上传；采集开关按原防抖规则提交最终有效修改，不逐次输入上传   |
| S6-04 | 修改主题、保留天数、CDP、开发者模式和列宽                           | 本机保存正常；新增配置上报次数为 0                                       |
| S6-05 | 修改后断网或让服务返回限流/临时错误，再恢复网络；另外测试断网后重启 | 修改本机有效，状态显示待上报；队列恢复后自动补传并清除已确认项           |
| S6-06 | 上报期间继续编辑，或让响应超时后重试                                | 后续修改不被旧响应标成已上报；同设备顺序正确，同一操作不重复应用         |
| S6-07 | 上报时登录失效；另提交一个永久校验失败操作                          | 登录失效暂停请求并等待重新登录；校验失败显示原因且不无限重试，不误报成功 |
| S6-08 | 云端其他设备修改配置，本机仅完成自己的保存                          | 本机仅显示“修改已上报”，不额外整份拉取；他端变更在本机下次冷启动生效     |

阶段完成标准：所有共享设置的增改删均验证，所有本机偏好均验证无云请求；断网、重启、超时重发三条恢复路径均完成闭环。

## 第七步：从当前电脑初始化配置

开发内容：提供由当前电脑执行的一次性导入动作，读取现有设置及凭据库中的密钥，校验后初始化云端。先在开发环境验证，最终正式初始化使用同一流程。其他客户端仅等待云端就绪，不自动上传各自的旧配置。

交付物：初始化工具或软件内入口、导入前后字段及引用对照记录、失败重试和重复执行验证。导入检查记录只写密钥是否存在及验证结果，不写密钥值。
