# AI 正文内容整理：样本对比、提示词迭代与集成计划

日期：2026-11-10（北京时间）。状态：已完成样本扩展、V1–V6 真实模型迭代及功能集成；最终验证见[实施记录](ai-body-organization/README.md)。下文保留首次计划及当时判断，最终冻结规则以实施记录为准。

## 1. 目标与交付顺序

在“采集与 AI 处理 → AI 处理规则”中增加 **正文内容整理**，在“提示词模板”中增加 **正文整理** 用途和内置 **正文整理提示词**。执行顺序为：获取渠道成稿和百度原文 → 分析整理规律 → 使用真实模型多轮优化提示词 → 接入当前采集流程 → 验证正文保真及失败回退。

首次计划阶段仅交付计划和可追溯的首批证据，当时未调用正文整理模型。后续实施按本计划推进，未修改真实 CMS 文章。

产品默认采用结构整理：改善分段和图文对应，保留新闻事实、正文内容和来源信息。是否需要额外删减，必须从配对样本和格式化中间结果得到依据，不能把“整理”直接实现成摘要或全文改写。

## 4. 阶段一：补齐可对比的完整样本

每个样本保留三份独立数据：

| 数据                        | 用途                                           |
| --------------------------- | ---------------------------------------------- |
| A：百度原文及项目采集器输出 | 确认完整正文、图片和后续页，作为不可变原始素材 |
| B：现有后台格式化结果       | 区分标签规范、图片转存和正文整理各自造成的变化 |
| C：渠道关联文章的 CMS 成稿  | 分析编辑后的段落、图文组合、图注、来源和分页   |

执行步骤：

1. 将首批 4 篇通过项目现有 WebView / CDP 采集逻辑回放，检查标题、作者、完整正文及分页；与本轮浏览器快照核对。采集、登录验证及后续页沿用既有能力。
2. 使用现有格式化协议获得 B；先核对该请求是否涉及图片转存或上传，只在隔离调研/开发者模式下执行。研究流程停止在本地结果，不进入 CMS 文章提交分支。
3. 分别比较 A→B 和 B→C，建立“文本块 / 图片 / 图注 / 小标题 / 来源 / 分页”的对应关系，人工查看疑似移动和删减。
4. 为图片建立本地编号，必要时比较画面与尺寸；不同 CDN URL 不直接判为不同图片，不能把来源 URL 当作可稳定匹配的唯一标识。
5. 补充至少 8 篇配对文章：共至少 12 篇，覆盖短文、长文、多图、无图、长引语、图注、来源署名等。原 4 篇及另外 4 篇用于开发，额外 4 篇作为冻结后的留出集。
6. 记录采集时间、文章版本/更新时间、HTML 与图片清单指纹、采集方式和完整性。来源无法配对、内容已发生实质更新或原文不完整的样本不进入准确率分母，单独说明原因。

阶段交付：样本清单、三份快照、差异报告和规则说明。真实正文保存在本机调研目录；Git 中仅加入提示词版本、必要的非正文指标和明确标注的演示用例。留出集的期望编辑结果不放进提示词。

## 5. 阶段二：确定整理规则和模型输出契约

### 5.1 首版规则候选

- 保留正文叙述的事实、措辞、标点和先后顺序，不摘要、不补写背景、不改写引语，不把观点改成结论。
- 在完整句末拆分过长段落，按语义组织自然段；段长先按样本分布调参，避免预先固定“每段必须两句”等规则。
- 图片与其连续图注作为一个组合处理；只有结构依据或人工标注充分时才绑定图注，不能凭短句长度猜测。
- 允许评测图片组合在对应完整句/段边界附近的位置建议；默认保持图片组合之间的顺序。涉及跨小节移动、孤立图注或无法证明图文关系的建议拒绝应用。
- 来源、记者、编辑和审核署名完整保留；不为缩短正文删除。页面关注、举报、推荐等非正文控件由有确定依据的本地清理规则处理。
- 不根据本批图片数量差异启用删图；不能生成新图片、改写图片地址，或将正文图替换成标题图。
- 正文整理不承担分页。关闭 AI 分页时，不新增分页符；已有分页遇到拆段或移动时作为受保护边界，不能安全映射则保留输入排版。开启分页时，再由既有分页服务处理整理结果。

规则冻结前，要用 B→C 证据复核上述候选；存在争议的历史排版单独记录，不强求像素或 HTML 字节完全一致。

### 5.2 推荐的受约束输出

优先沿用项目分页服务的思路：**模型返回已有节点的操作建议，本地代码负责还原 HTML**。不让模型重新输出整篇正文。

输入包含标题、带稳定编号的内容块、可拆分句子编号、可移动图文组合及允许的边界。图片使用编号和本地确认的关联信息，不发送图片 URL 或图片二进制；采集正文中出现的角色、命令、链接和 JSON 均是文章数据，不得当作指令执行。

建议在评测工具中先验证如下输出形状，再固化为前后端类型：

```json
{
  "version": 1,
  "split_after": [{ "block_id": "B3", "sentence_id": "S2" }],
  "move_groups": [{ "group_id": "G1", "after_block_id": "B5" }]
}
```

编号由本地程序生成，模型不能创建文字、URL 或图片。需拒绝未知编号、越界拆分、重复引用、移动冲突、图注脱离图片和不支持的版本。输出无操作时允许返回空数组，不为证明“做了整理”强制改变正文。

句子拆分必须保留原 HTML 中的合法映射和原始文字片段。复杂列表、引用、混排媒体等无法安全拆分时整体保留，不通过重新序列化纯文本丢弃格式。计数字段正式采用非空白 Unicode 标量值数，明确与前端 UTF-16 光标偏移的换算。

## 6. 阶段三：真实 AI 调用与至少三轮自我迭代

### 6.1 评测方式

建立独立评测工具，读取已保存的模型提供商、协议兼容设置和原生凭据引用；不新建或猜测 AI 接口，不把密钥写入脚本、证据和命令行。优先使用拟绑定正文整理模板的真实模型，每轮固定输入和推理/输出参数；若更换模型，需要重新跑全部开发集。

现有分页调研中的模型和通过率只作工具参考，不能作为本次正文整理测试结果。真实请求与本地规则回放分别标记；没有模型配置、请求失败或没有计量时如实记录，不能以人工改稿或演示响应代替真实 AI 实测。

### 6.2 迭代安排

| 轮次   | 动作                                                                  | 必须保存的证据                                          |
| ------ | --------------------------------------------------------------------- | ------------------------------------------------------- |
| 基线   | 回放原格式化结果、当前流程，建立无正文整理的对照                      | 输入指纹、段落/图文问题清单、当前分页效果               |
| V1     | 根据样本规律编写最小提示词，跑全部 8 篇开发样本及演示边界用例         | 模型输出、实际本地渲染结果、逐条校验和失败分类          |
| V2     | 针对 V1 失败修改提示词，重跑相同全集                                  | 提示词差异、解决的问题、新增退化、与 V1 的对照          |
| V3     | 精简并明确图注、长段和异常输入约束，重跑全集；冻结后再跑 4 篇留出样本 | 最终版本及指纹、开发集和留出集独立结果                  |
| 稳定性 | 冻结版本对截图 4 篇各额外运行 3 次                                    | 波动、失败率、延迟、输出 token 和费用计量（若接口提供） |

至少完成三轮真实评测。每轮由“模型生成 → 本地应用 → 自动校验 → 查看渲染/差异 → 修订提示词”组成；不能只在对话里改写三遍提示词，也不能只看模型自评分。

未达标时继续 V4 / V5；若使用留出样本修改了提示词，该批样本转为开发集，并另外选取未使用的样本做最终留出验证。达到次数不代表验收通过，所有失败和费用都要计入记录。开发期迭代是本次调研流程，生产任务仍只执行一次整理请求，不自动循环付费纠正。

### 6.3 验收指标

| 指标            | 目标及判定                                                                                             |
| --------------- | ------------------------------------------------------------------------------------------------------ |
| 正文保真        | 全部受保护文字片段覆盖 100%，叙述顺序保持；人名、数字、日期、引语与署名无增删改                        |
| 图文保真        | 首版全部输入图片保留且各出现一次；图注绑定、图片组合顺序及合法边界检查通过                             |
| HTML 安全与兼容 | 不增加脚本、事件属性、危险 URL；可由现有内容链与编辑器安全读取                                         |
| 合同校验        | 非法 JSON、编号冲突、越界、截断及不支持结构全部被明确拦截                                              |
| 编辑质量        | 开发集和留出集逐篇查看分段、图文衔接、图注位置和来源完整性，至少消除已标注的可修复问题且无新增严重问题 |
| 分页独立性      | 整理开关与分页开关的四种组合符合定义，无新增首尾空页、孤立图注或半句断页                               |
| 稳定性与成本    | 分别报告首次成功率、稳定性复跑结果、耗时及实际计量，不以重试后成功覆盖初次失败                         |

自动硬性检查和编辑检查同时通过才推荐集成默认提示词。若模型无法稳定改善版式，保留关闭默认值和完整失败记录，不以删减约束来提高通过率。

## 7. 阶段四：集成当前项目

### 7.1 设置和提示词入口

1. AI 处理规则增加“正文内容整理”开关，建议默认关闭，说明“整理段落与图文位置，保留原文内容；失败保留原排版”。显示默认模板、绑定模型及“配置提示词”入口。
2. 提示词模板增加独立“正文整理”用途、内置“正文整理提示词”，支持新增、编辑、复制、删除、绑定模型和独立默认项。
3. 建议新增用途标识 `bodyOrganization` 和开关 `aiOrganizeBody`；模板变量首版采用 `{{title}}`、`{{blocks}}`。不用标题候选数量、标题字数上限或分页页长驱动整理。
4. 桌面及 Android 的路由用途参数、模板列表、独立草稿、变量插入、未保存保护和手动同步锁定均覆盖新用途；新建模板不能误填标题提示词或显示分页参数。
5. 开关沿用采集设置的 500ms 自动保存，离开时补存、入队前等待保存，保存失败保留输入并阻止本次入队。

### 7.2 类型、数据和同步

- 按 `UI → 业务服务 → 类型化 IPC → Rust → SQLx` 扩展现有链路。新增契约先在评测工具验证，再落到 `contracts.ts`、Rust 类型和必要的 IPC；组件不得直接调用 invoke 或 SQL。
- 新增 SQLx 迁移，不改已执行的历史迁移。扩展 `ai_prompt_templates.purpose` 的 CHECK 时完整保留既有模板、模型外键和每用途唯一默认索引；必要时重建表并做旧库迁移测试。
- 内置整理模板仅在迁移时插入，绑定模型初始为空，不覆盖用户自定义提示词或旧用途默认项；删除后重启不擅自恢复。
- 新字段对旧设置和旧任务默认关闭，缺少整理快照的历史任务不从当前配置临时开启整理。
- 同步协议需同时覆盖用途、默认整理模板引用、整理开关、变量校验和字段差量。当前严格校验不允许直接假定新增字段向后兼容；实施前确定服务端/客户端能力或协议版本策略，验证旧快照升级和旧客户端行为。
- Worker 先完成本地协议、测试和 dry-run。线上服务升级顺序、旧客户端兼容范围及实际部署应单独记录，不能以“本地通过”宣称跨设备已生效。

### 7.3 任务执行和检查点

建议维持现有元数据阶段顺序，将整理插入分页之前：

```text
完整原文 → 后台格式化 → 现有 AI 元数据
  → 正文整理（本地块映射 → 模型建议 → 校验 → 本地 HTML）
  → 现有 AI 分页 → prepared → 现有提交/调试分支
```

入队时固定整理开关、模板 ID、提示词文本、模型执行配置、输出契约/规则版本。凭据只保留原生引用，执行时从凭据库读取。运行中修改模板或模型不影响已入队任务；手动重试继续使用原 AI 快照。

整理开启但默认模板不存在、未绑定模型或配置无效时，在入队配置检查中给出具体原因及设置入口，不静默选择其他用途模板。历史任务快照不完整时按既定兼容策略记录跳过原因。

为整理结果保存独立阶段检查点或等价的带阶段标识记录，包含输入指纹、规则版本、输出 HTML 和处理结果；不能把它覆盖到不可变原文或 `formatted`。重启、失败重试优先复用有效检查点，避免已经完成的 AI 请求重复付费；有 `prepared` 的旧任务继续复用最终结果。

模型超时、截断、内容过滤、无效结构、无法映射或普通网络错误：整步回退到整理前 HTML，记录清晰警告，再按分页开关执行既有分页。任务取消、账号变化、认证失效和存储错误仍停止，迟到结果不能保存到新会话。整理警告不可标成整理成功，也不能改变 CMS 提交结果的定义。

| 正文整理 | AI 分页 | 预期行为（不含已有元数据请求）                         |
| -------- | ------- | ------------------------------------------------------ |
| 关       | 关      | 保留现有处理结果，零整理/分页请求                      |
| 开       | 关      | 请求整理一次，通过后应用结构调整，不新增分页           |
| 关       | 开      | 保持当前 V9 分页行为，零整理请求                       |
| 开       | 开      | 整理校验通过后分页；整理失败则对整理前结果执行现有分页 |

## 8. 阶段五：验证与交付

测试重点是有业务风险的边界：

- 前端：新用途默认模板隔离、新建/复制内容、绑定模型与配置跳转、自动保存失败、未保存草稿、桌面及 Android 展示。
- Rust：提示词变量、结构输出、Unicode 拆段映射、文字和图片覆盖、图注保护、原 HTML 回退，以及模型截断、超时和取消。
- 任务/数据库：旧数据迁移、任务快照固定、四种开关组合、检查点复用、重启/重试、退出换号、原文不被覆盖。
- 同步：旧/新快照、默认模板引用、差量上传、同步中锁定、未保存设置阻挡及不兼容客户端的明确行为。
- 集成：用本次真实样本在开发者模式回放，检查实际 `newsText` 和现有编辑器渲染；用本地 HTTP/IPC 替身验证提交字段，真实 CMS 不用于自动化写测试。
