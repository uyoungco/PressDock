## 现状审查

基于 `src/pages/Import/index.tsx` 和 Ego 中的真实 React 页面，使用同一组 8 条隔离演示记录观察：

1. 页头和两张卡片分别解释采集流程，说明重复；1440×900 时表头位于约 y=422，列表开始得晚。
2. 现有三列初始总宽为 1220px，而表格可视区域更窄；即使是桌面宽屏，也要横向滚动。
3. 状态胶囊、错误和警告在同一列竞争；终态行持续暴露删除按钮，主要处理动作不够突出。
4. 列表在窄窗时操作容易堆叠；标题之外缺少简明的来源、入队时间辅助信息，这些值现有任务已经提供。

现有页面已经使用中性背景和统一图标，无需另造品牌、营销插画、统计卡或新功能。本稿集中改密度、信息层级和任务操作。

## 五行方向

- **产品：** 帮助新闻编辑连续提交文章链接，并处理后台采集任务。
- **性格：** 紧凑、克制、明确。
- **视觉参照：** 编辑台与校样单；纸白内容区、中性灰分隔线、校样蓝主操作。
- **重点：** 一处蓝色采集入口；语义色集中在任务状态与人工处理提示。
- **识别细节：** 用细状态点和需要处理记录左侧的细标记组织采集队列，颜色始终伴随文字。

## 页面布局

保持“页头 → 提交链接 → 采集记录”的顺序，将两张大卡片整合成一个工作区。

| 区域       | 设计约定                                                               |
| ---------- | ---------------------------------------------------------------------- |
| 页头       | 22px / 28px、500 字重；一行流程说明；右侧放“采集设置”快捷入口          |
| 工作区     | 白底、1px 中性边线、12px 圆角；无常驻侧面板                            |
| 链接输入   | 标签、输入、开始采集横排；输入及主按钮高 36px；保留回车提交            |
| 输入辅助   | 左侧说明后台继续执行；右侧说明调试仅保存本地；错误紧贴输入呈现         |
| 列表工具栏 | 高 48px；“采集记录”、记录数、需处理数在左；日期及刷新在右              |
| 表头       | 高 32px；新闻内容、状态、操作三列；随列表固定                          |
| 常规行     | 高 60px；异常文字和窄窗操作自然换行，不截断必要错误信息                |
| 新闻内容   | 标题吸收剩余宽度；副行展示来源域名与创建时间；标题保持打开原文         |
| 状态       | 状态点 + 明确文字；异常说明位于副行；不使用装饰性进度条                |
| 操作       | 常用动作行内显示；删除等低频动作进入“更多”；菜单支持 Esc 返回触发器    |
| 滚动       | 记录区独立纵向滚动；输入、日期、刷新和底部说明保持可达；无整页横向溢出 |

1440px 时状态列 248px、操作列 272px，标题列占剩余宽度；1200px 以下分别收为 208px、232px，必要时操作换行。实际实现继续复用表格列偏好，不强行覆盖用户已有列宽。

“采集设置”指向已有 `/settings?tab=harvest&returnTo=import` 路径，不新建设置面板。

## 状态与交互

预览呈现：处理中、网页验证、排队、已添加、失败、提交结果待确认、调试完成。未在主稿逐一列出的状态继续保留现有业务规则，不删除状态或增加后台行为。

| 任务状态                      | 可用动作及约束                                               |
| ----------------------------- | ------------------------------------------------------------ |
| 排队 / 运行                   | 取消；阶段文案沿用现有 `harvestStatus`                       |
| 等待网页验证                  | 打开来源、验证完成后继续；取消放“更多”                       |
| 等待选择标签页                | 保留现有候选标签页弹框、候选失效与稍后选择规则               |
| 失败 / 中断 / 取消 / 等待登录 | 按现有状态规则显示重试；仅允许的终态提供删除                 |
| 已添加 / 调试完成             | 打开原文、删除记录；调试完成明确“未提交 CMS”                 |
| 提交结果待确认                | “CMS 已添加”“CMS 未添加”均先打开核对确认框；不会直接重新提交 |

删除确认保留完整说明：删除本地记录及未被草稿引用的数据，CMS 文章保留；再次采集可能再次提交 CMS。

输入只支持当前已支持的文章域名，不增加批量粘贴、拖文件、自动发布、状态筛选或任务排序功能。来源域名从 URL 派生，时间取任务创建时间，不增加接口字段。重复提交保护、持久任务、事件订阅、请求失败保留输入等继续沿用现有实现。

## 适配边界

本稿以桌面工作流为主。1024 / 768px 时操作和异常文案可增加行高，保持纵向列表；390px 预览采用卡片和 40–44px 触控尺寸，用于观察收窄后的内容可达性。

手机预览是静态内容适配，不代表已回归或准备替换 Android 的真实采集行为。后续实现建议保留现有 Android 分支，包括“前台执行、后台中断、返回重试”的说明，不把桌面后台执行文案带入手机。

## Unslop 九步落实

1. **间距：** 工作区内 8 / 12 / 16px 分组，页面边缘沿用 28px；常规记录统一 60px。
2. **颜色：** 表面保持中性；校样蓝用于主操作；绿、赭、红分别表达完成、等待、失败。
3. **图标：** 沿用线性图标语汇；无 emoji、AI 闪光或装饰图标。
4. **文案：** 合并重复说明；“已添加到 CMS”与“入队”分开表达；异常给出下一步操作。
5. **字体：** 使用系统界面字体；正文 13px、辅助信息 12px，页头 22px；时间采用等宽数字。
6. **布局：** 一条采集带接一张记录表，标题列伸展；输入区和工具栏固定、记录独立滚动。
7. **细节：** 状态不用胶囊；低频操作归入菜单；破坏性动作二次确认；键盘焦点清晰。
8. **视觉：** 文章标题与任务状态构成主体，不生成插画，不用装饰图填充工作区。
9. **动效：** 只有控件颜色反馈；不使用循环呼吸、跳动或布局动画；支持减少动态效果。
