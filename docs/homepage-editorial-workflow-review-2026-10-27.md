# PressDock 新闻首页维护工作流评估

日期：2026-10-27  
评估依据：你描述的实际工作流程、当前仓库代码、README 和现有接口文档。

本报告区分代码已有能力、产品建议与尚待核实的 CMS 协议。本次只阅读仓库并编写报告，未启动开发服务器、登录网站、调用线上 CMS 或修改业务代码。“已有实现”不等于本次完成了桌面端或线上验收。

## 1. 结论与开发重点

**最值得投入的方向，是把“导入 → 正文编辑与分页 → 加入渠道 → 标题和图片适配”接成一条连续工作流。**

现有采集队列、图片处理、渠道管理已经具备可复用的基础。最大的断点在中间：真实采集文章没有进入现有编辑草稿，正文人工处理与后续渠道适配之间也缺少关联。

建议重点开发：

1. **真实文章编辑工作台**：处理段落、换行、插图，并保存回同一篇 CMS 文章。
2. **可视化分页助手**：自动生成分页初稿，直接调整分页点、合并页面、移动图文并检查短页。
3. **按渠道适配标题和图片**：渠道标题自动限字，一张原图生成多个渠道规格，减少复制、数标题字数和重复裁图。

渠道标题规则、渠道选择和新增默认值可以先交付。完整编辑器必须先核实 CMS 正文读取与更新协议。沿用你当前“先导入 CMS，再人工处理”的顺序，不给每次导入额外增加强制编辑确认。

## 3. 四个主要断点

### 3.1 真实采集与编辑草稿分离

采集保存原文、格式化结果和最终提交结果，之后创建 CMS 文章。现有文章列表则从 `drafts` 关联原文读取；采集没有自动创建对应草稿，内容编辑导航还固定指向 `/editor/demo-1`。[E3、E4、E6、E14]

建议导入完成后能在真实文章列表找到同一篇文章，并从任务状态操作区进入编辑。首次编辑建立独立草稿，以与 CMS 当前版本对应的正文作为底稿。如果暂时只能取得本地采集快照，应显示快照时间和同步状态。

### 3.2 自动分页不能人工精修

当前分页以约 240 个非空白字符为目标，剩余内容不超过 280 字时可收为一页，尾页不足 100 字时尝试平衡，并优先在语义组或原段落之间切分。单个长段落或长语义组可以超出目标长度，这些数值不是每页必然满足的硬限制。[E7]

已有算法能减少初次排版工作；需要补充的是你可以直接判断和调整的界面：这里是否适合翻页、这页是否太短、图片是否应当跟随下一段。

### 3.3 文章信息进入渠道表单时需要重新搬运

新增渠道素材从空表单开始。编辑表单中的渠道、子渠道仍为文本输入，筛选区却已有可搜索的真实渠道选择器。[E8、E9]

建议从文章提供“加入渠道”，带入可确定的文章信息；从渠道列表点新增时，带入已提交的渠道、子渠道和日期筛选，并允许调整。

### 3.4 渠道要求没有形成统一校验

图片要求已经可以按渠道、子渠道和图片字段保存；标题没有同样的规则。手填图片地址或修改渠道后，也不会自动重新处理图片。[E10、E11]

建议在表单里同时展示标题与图片要求，保存前检查相关项目。尚未取得图片尺寸或无法确认展示状态时，显示待检查，不能直接判为合格。

## 5. 核心功能设计建议

### 5.1 真实文章编辑工作台

首版聚焦你每天确实会做的操作：

- 保留段落、换行、图片、图注与分页标记，直接看到排版结果。
- 在光标处插图，支持本地文件、剪贴板和文章已有图片。
- 调整段落与图片位置，支持拆分段落、合并段落、清理连续空行。
- 切换或并排查看原文和编辑稿，采用自动整理前可看到差异。
- 自动保存本地草稿，中断后恢复，允许撤销最近一次整理或分页。
- 分别提示“本地草稿已保存”和“已同步 CMS”，远程失败时继续保留草稿。

AI 适合提供结构整理建议；字数、分页标记、图片规格检查使用确定性规则。涉及删除或改变含义时应能看到差异再采用，来源和图注也保留可追溯信息。

**关键前提**：当前仓库有文章创建、格式化和分类读取，未发现真实 CMS 正文读取、更新实现。本地 `get_article`、`save_draft` 操作的是 SQLite，不能当作远程正文接口，也不能依据常见 REST 命名猜测后台支持什么协议。[E4、E6]

需要确认更新字段、是否要求完整记录、分页保存格式、是否触发发布或重新生成页面，以及如何避免覆盖你在 CMS 网页里做过的新修改。如果协议暂未确认，可以先做本地编辑与导出，但只能称为编辑辅助；对已导入文章不能通过再次创建来代替更新。

### 5.2 可视化分页助手

建议采用“页面导航 + 当前页编辑 + 预览”的组织方式。导航显示每页文字数量和图片数量，点击定位，直接调整内容。

首版能力：

1. **一键生成分页初稿**：复用现有算法，处理当前编辑稿，避免重新采集或还原原文。
2. **手动增删分页点**：在段落边界插入、移除，并与前页或后页合并。
3. **跨页移动图文组**：整段或图片与图注一起移动，减少复制粘贴 HTML。
4. **保留已确认的分页点**：重新分页只调整选中范围或未锁定区间。
5. **异常定位**：标出空页、明显短页、超长段落和图注分离；纯图片页按文章类型判断，不直接判错。
6. **CMS 往返一致**：正确读取和输出 `[!--empirenews.page--]`，保存后文字、图片不丢失、不重复、不乱序。

先沿用现有数值作为默认值，只开放你实际需要调整的目标长度与尾页长度，不必首版就做复杂规则引擎。图集与普通图文确有明显差异时，再增加相应规则。

分页应同时关注人工处理时间和实际阅读深度。页数是排版结果，PV、阅读完成率与收益是否改善，需要真实数据验证，不把生成页数直接当作阅读效果。

### 5.3 渠道标题助手

这里管理渠道素材的 `Title`，与文章标题分别保存。采用渠道标题候选不应修改文章标题。

- 按“渠道 + 子渠道”保存字数上限，实时显示“当前字数 / 上限”和超出数量。
- 输入、粘贴、采用 AI 候选与保存使用同一套计数规则。
- AI 自动带入当前子渠道限制和表达要求，候选旁显示字数。
- 切换渠道后重新校验，保留已编辑标题供调整。
- 表单使用“渠道标题”“文章链接”“摘要”等中文业务名称，必要时附后台字段名。

现有 AI 按 Unicode 字符计数，标点计入；实际渠道如果按汉字、英文半角或显示宽度计算，需要先确认并统一。未配置规则的渠道不要擅自套用硬上限。[E11]

字数校验无需 AI。AI 用于在事实不变的前提下提供合适表达；超长候选继续过滤并说明，不直接截断句子。

### 5.4 从文章直接加入渠道

```mermaid
flowchart LR
    A[百度寻找素材] --> B[导入并创建 CMS 文章]
    B --> C[打开真实文章编辑]
    C --> D[段落、插图与分页]
    D --> E[保存草稿并同步 CMS]
    E --> F[选择渠道和子渠道]
    F --> G[适配渠道标题与图片]
    G --> H[检查后保存渠道素材]
    H --> I[核对实际展示状态]
```

“加入渠道”带入可以确定的标题初值、摘要、作者和本站文章链接，再由你调整渠道标题与配图。原始来源链接用于追溯，不能直接代替本站文章地址。渠道标题、渠道图片作为独立版本保存，文章更新后不静默覆盖它们。

必须核实两个细节：

1. 文章创建只返回可选 `cmsArticleId`，成功不保证拿到 ID。缺少可靠 ID 或本站链接时需要补充核对，不能凭来源链接猜关联。
2. 现有新增渠道输入没有 `ArticleId`，创建渠道素材只返回成功布尔值。需要确认后台怎样关联文章、取得素材 ID 并回查保存结果，不能直接自行增加请求字段。[E4、E8、E12]

单渠道流程稳定后，再考虑多渠道批量加入。每个目标分别显示成功、失败或待核对结果；多次独立写请求不能表现为后台原子事务。结果未知的写入也不自动重发。

### 5.5 一张原图适配多个渠道

现有编码、裁剪和压缩能力已经比较完整，重点补充原图复用与多规格编排。[E10]

- 保留选中的原图，在同一界面列出目标渠道 `TitlePic`、`TitlePic2` 的处理结果。
- 读取已保存预设，显示实际像素和文件体积，允许每个规格单独调整裁剪框。
- 首版以人工确定构图为主，之后再评估主体位置记忆或自动识别。
- 两个字段只有规则一致且你确认使用同一构图时才复用结果；不同规格从原图重新生成。
- 更换渠道后标出不合新规则的图片，提供重新处理入口，不自动上传替换。

正文原图与渠道缩略图分别保留，避免为满足渠道小图规格而缩小正文图片。不同宽高比需要分别检查人物、主体和图中文字，不能保证一次裁剪适配所有位置。

### 5.6 正文配图收集与复用

先解决“找到图片之后”的成本：从搜索引擎选好图后粘贴到编辑器，或放入当前文章的图片栏，再插入光标位置。正文已有图片也可以供渠道封面选择。

建议保留来源页面和说明，减少同图反复下载。搜索词建议和搜索入口可以后补；内嵌完整搜图、自动下载外站图片、自动判断用途不属于首版必需项。

现有上传路径服务于渠道图片。正文能否复用同一图片地址、是否需要额外转存、格式和可访问性要求，都需要核实。当前图片读取许可围绕会话中出现的渠道图片，不能直接假定正文任意远程图片已经可以预览。[E10、E12]

## 6. 其他值得做的提效功能

### 6.1 真实的当日维护清单

工作台显示实际工作并提供下一步入口：

| 维度     | 建议状态                                         |
| -------- | ------------------------------------------------ |
| 导入     | 正在处理、已添加 CMS、失败、提交结果待确认       |
| 编辑     | 待人工处理、有未保存修改、本地已保存、CMS 未同步 |
| 渠道     | 待适配、标题待调整、图片待处理、已保存渠道素材   |
| 展示核对 | 未核对、已核对，以及实际依据与核对时间           |

这些维度分别表达，不用一个“完成”同时表示导入、编辑、保存渠道和上线。现有工作台按本地稿件计算数量，不能直接用来代表真实 CMS 全量工作。[E13]

保存前检查仅覆盖当前操作相关项目，例如标题超限、必填图缺失、已知图片规格不符、正文未同步，并能够直接定位字段或页面，减少每次重复点选长清单。

### 6.2 批量链接与待选素材篮

现有队列支持连续单条提交，可补充一次粘贴多行链接：解析、列出无效项与已有任务，再交给同一个队列。首版不需要增加并发采集。[E1、E2]

素材篮用于暂未决定导入的链接，可记题材和备注，明确显示未采集、未导入。如果你通常找到即导入，先只做批量入队。

当前 URL 规范化会去掉片段，不能因此视为跨百度链接形态、参数差异或转载的内容查重。可以核实文章标识后补同文提示；标题或正文相似只能提醒核对，不能直接跳过。

### 6.3 一稿多渠道版本表

同一篇文章只编辑一次正文，版本表按行展示不同渠道位置的标题、封面、规则和保存结果。这样可以直接发现哪个位置还没适配，减少来回打开新增弹窗。

这项功能是否提前做，取决于一篇文章平均进入几个渠道。如果多数只投一个渠道，先做好单渠道入口。

### 6.4 渠道组合预览

保存前检查卡片图片、标题换行和相邻内容，发现重复配图或相近标题。预览依赖真实字体、行数、卡片尺寸和裁切规则；缺少规则时标为近似预览。

完整首页版面管理需要确认位置映射、排序和权限。现有排序只处理查询的当前页，不能直接等同于全首页布局编辑。[E12]

### 6.5 围绕分页与渠道做效果复盘

先记录本工具能可靠取得的操作数据。接入真实统计后，再分别观察：

- 渠道曝光和点击：评估标题、图片与位置。
- 首屏、第二页及后续各页到达和阅读完成：评估分页后的阅读过程。
- 会话浏览页数、停留和广告收益：遵循统计平台口径，分别观察。

比较分页长度时尽量按相近题材、渠道位置和流量条件分组；不能仅凭某篇总 PV 较高就认定分页更好。刷新、重复访问和收入口径也需要确认。

当前代码没有访问分析或广告收益接入。可以展示分页数作为排版信息，但不生成预测收益。暂时没有接口时，后续可评估导入现有统计报表，无需先建设完整数据平台。

## 7. 建议交付顺序

| 阶段                     | 交付内容                                                                      | 你能够获得的能力                             |
| ------------------------ | ----------------------------------------------------------------------------- | -------------------------------------------- |
| 第一阶段：规则与协议     | 渠道标题规则；渠道/子渠道选择；新增带入已提交筛选；核实正文与文章关联协议     | 当下渠道操作更快，编辑器有可靠接入依据       |
| 第二阶段：核心编辑闭环   | 真实文章入口、独立草稿、正文图片编辑、可视化分页、本地恢复及已核实的 CMS 更新 | 在 PressDock 完成人工处理，保存回原 CMS 文章 |
| 第三阶段：减少重复适配   | 文章加入渠道、原图多规格处理、保存前检查、真实当日清单；按需补批量链接        | 少复制、少重复处理，容易跟踪漏项             |
| 第四阶段：按使用数据扩展 | 多渠道版本表、组合预览、更多来源、效果复盘                                    | 根据高频重复操作与实际效果继续投入           |

**最小完整目标**：一篇百家号素材导入 CMS 后，在 PressDock 打开真实文章、插入一张图、调整段落、生成并修改分页、保存回同一篇文章，再带入渠道表单，完成合规的渠道标题与图片。先走顺这一篇，再扩展批量能力。

暂不优先做全网自动搜索、全自动选图、整篇自动改写、自动正式发布、复杂多人审批和缺少数据来源的收益预测。这些并非当前描述中的主要手工断点。

## 8. 验收与收益衡量

以下为未来功能验收场景，本次未新增或运行相关测试：

1. 导入后进入的是同一篇真实文章，能核对 CMS 标识，不进入演示稿。
2. 图文、图注、分页打开后不丢结构，保存并重新读取后保持一致；原始素材独立保留。
3. 手动分页能够撤销和恢复，再次自动分页不无提示覆盖已确认结果。
4. 本地保存与远程同步分别反馈；网络中断草稿仍在，结果未知不自动重建文章或重复提交。
5. 切换子渠道后按新规则检查标题和图片，文章标题与正文原图不受渠道操作影响。
6. 渠道保存后能核对目标记录；只确认保存成功时，不同时显示正式发布或首页已展示。

建议先记录约 20 篇日常稿件的分步骤时间、切换次数与返工原因，覆盖常见图文类型，并区分人工操作时间与等待采集、上传的时间。

随后比较每篇人工编辑时长、分页调整时长、每个渠道适配时长、标题超限返工、图片重处理以及重复入库或待核对数量。没有基线前，不承诺提升百分比。

可以用以下公式评估工具价值：**每天节省时间 = 每日篇数 × 每篇节省的编辑时间 + 每日渠道操作次数 × 每次节省的适配时间**。PV 与收益另行使用真实数据评估。
