## 步骤 3：云端服务

交付 `GET bootstrap`、`POST initialize`、`POST operations`、`POST check`，沿用固定 CMS `CurrentUser` 验证。客户端不能指定用户 ID、SQL、上游主机或主密钥。只有通过真实 CMS 鉴权后才能读取设置和密钥。

D1 原子事务包含版本检查、字段合并、密钥密文、永久墓碑、设备顺序和操作回执。初始化及操作按稳定 UUID 和原请求字节计算独立 HMAC，重复请求返回原回执；同 operationId 的不同内容被拒绝。`check` 只查回执，不重新应用操作，用于冷启动时移除已提交但丢失响应的待传项。

## 步骤 4：本地快照与密文队列

`0010_settings_sync.sql` 增加设备序号、有效代际、密文请求、队列、初始化回执及凭据垃圾回收。请求整体使用随机 AES-GCM 密钥加密后存 SQLite，解密密钥放原生安全凭据库。每次密钥修改产生独立引用，旧请求不会误用最新密钥。

快照先写并读回原生凭据，再以 SQLx 事务切换配置与有效代际。失败保留旧有效配置。每次准备原生凭据前先持久记录候选引用，启动时清理未提交的准备结果；垃圾回收检查当前提供商、有效代际、密文请求、恢复副本及历史采集任务快照引用后才清除旧凭据。准备、提交、确认和回收共用数据库旁的进程间文件锁，避免另一进程回收正在准备的引用，锁随进程退出释放。

`0012_settings_sync_recovery.sql` 增加永久拒绝后的恢复副本表，保留本机共享配置、全部待传操作的原密文和凭据引用。恢复操作不包含密钥明文，不删除原文、草稿、任务或本机偏好。

## 步骤 5：冷启动读取

登录恢复后由 Rust 控制单次成功 bootstrap；前端状态轮询只读本机 IPC。重复挂载、窗口聚焦、后台返回、在线事件和运行中换号不重新下载完整配置。在线事件只唤醒上传。首次读取失败提供显式重试；有有效缓存则显示提示并使用缓存。身份变更通过 session epoch 丢弃旧响应。

S5-01—06 均有请求计数自动化，包括无缓存重试、缓存回退、待传覆盖云端新快照、已接受 create 的丢失响应回执核对，以及下载中退出登录。

Android 实机观察到 `读取 1 次，成功 1 次；上报 0 次，待传 0 项`。Home 后返回进程，读取仍为 1。另一次冷启动网络失败，显示“正在使用上次缓存，本次未能读取最新配置”，计数读取 1、成功 0，已有设置仍可用。没有清除用户安装数据来制造首次安装场景。

Windows 原生隔离库 `verify-download` 成功读取 Android 刚保存的标识，coldReads=1、revision=2、AI 请求=0、CMS 写入=0。它验证原生后端，不代替 Windows 打包界面与 macOS 生命周期验收。

## 步骤 6：差量保存与补传

提供商、模型、模板、默认关系、图片预设及五项共享采集 AI 规则接入业务服务和类型化 IPC。表单保留开始编辑时的基线，后端只发送改变的字段；成功保存后使用实际合并结果刷新本机表单。采集规则保留既有防抖，模板未保存不入队。

Windows 原生工具在真实开发 D1 完成提供商/模型/模板/图片预设增改删、默认模板切换、密钥创建/替换/清除、共享采集规则修改与恢复。本机主题、历史保留天数、来源方式/CDP/开发选项保存产生 0 个同步上传。测试后原演示配置恢复，AI 请求=0、CMS 写入=0。

原生运行时测试覆盖 429/503 等临时失败的持久退避、401 暂停、永久校验错误暂停、旧回执不确认新修改、稳定原字节重试、重开数据库补传，均通过。Windows 真实开发 D1 探测也完成数据库关闭/重开后补传，补传未新增 bootstrap。

Android 实机仅改变模型显示名称并保存：读取仍为 1，上报 1，待传最终为 0；Windows 随后读到该值。已将显示名恢复为原 `deepseek-flash` 并确认云 revision=3、手机待传=0，未改变实际模型 ID。

最终 Android release 包另做完整断网闭环：关闭 Wi-Fi/移动数据后仅改显示名为临时标识，本机立即生效并显示待传 1、`SYNC_NETWORK`；结束进程后离线重开，现有 CMS 登录恢复要求联网重试。恢复原有网络设置并重试登录后，使用缓存进入工作区，队列自动补传至云 revision=4，诊断为读取 1、成功 0、上报尝试 3、待传 0。随后恢复原名称并保存，云 revision=5、读取计数不变、上报尝试 4、待传 0；Home 后返回仍保持相同计数。网络设置均已恢复，未卸载或清数据。该流程证明真实进程结束后密文队列保留及补传；完整断网冷启动直接进入工作区仍受原有 CMS 登录校验限制。

永久校验错误会保留并暂停队列头，不无限重试，也不误报成功。设置页提供“恢复同步”：确认后以单个事务保留本机共享配置、全部待传密文及密钥引用，再退出待传队列；当前进程停止同步并提示完全退出后重启。下次冷启动读取云端，不重放已保留的副本，不撤销已经被云端接受的修改；取消或归档失败均保留原队列。前端确认/取消/失败、原生事务回滚、跨进程副本解密和重启后采用云端均已自动化验证。该入口不自动修正字段冲突，副本目前仅在原安装内保留，尚无浏览或导出界面；Android 已通过真实删除冲突的拒绝、取消、确认及重启恢复实测，详见下文。

## 步骤 7：当前电脑初始化

指定工具读取原 Windows SQLite 和系统 keyring，先 `VACUUM INTO` 备份，再校验完整配置和密钥；读取失败不发送缺失密钥的半份初始化。冻结的初始化请求与普通队列一样加密持久化，响应丢失后使用同 operationId 和原字节重试。

正式初始化的脱敏结果：配置内存比对一致；提供商 1、模型 1、模板 2、图片预设 6、密钥 1；下载密钥与本机在内存比较一致，未输出值；revision=1。完成后删除请求密文及对应解密密钥，保留一次性回执。重复执行返回 `alreadyCompletedLocally=true, uploaded=false`，没有再次导入。

隔离的新 Windows 本机库从正式云下载配置和密钥并明确发起一次 AI 测试成功；Android 新版本也下载密钥并实际返回“模型已返回可用文本”，无需重新输入密钥。此轮 Android 明确触发了两次连接测试，Windows 一次；没有以任何演示文本冒充真实返回。

S7-01、03 的真实云初始化及幂等、S7-04 客户端不自动导入、S7-05 新设备真实 AI 链路通过。S7-02 另在隔离 Windows 数据库和真实系统凭据库验证：删除专用演示密钥后，严格源读取返回 `SYNC_CREDENTIAL_STORE`，初始化记录为 0；恢复专用密钥后可继续准备。未破坏当前用户的真实密钥。

初始化专项自动化还验证冻结后关闭并重开数据库、再更改本机密钥，初始化请求仍与原字节及 operationId 一致，SQLite 不含演示密钥明文。Windows 原生专项另启动隔离子进程，冻结初始化请求并持有凭据文件锁后强制结束该子进程；重新打开数据库并执行垃圾回收后，原 operationId、请求字节及密钥仍可恢复，文件锁已自动释放。专用测试凭据均已清理，云请求、AI 请求、CMS 写入均为 0。这是上云前冻结阶段的真实进程故障测试；云端提交后的强杀已在后续独立专项补验，见下文。
