# 采集开发者模式

更新日期：2026-10-26。

## 使用

1. 重启更新后的桌面程序并登录，进入“系统设置 → 采集与 AI 处理”。
2. 按需启用 AI 判断分类、AI 生成标签、AI 生成摘要、AI 正文整理；“自动内容分页”继续使用本地算法，单独开启不请求 AI。
3. 勾选开发者模式，等待即时保存成功后按 F12 打开主窗口 DevTools，查看 Console。
4. 在素材导入页添加链接。调试任务照常采集、CMS 格式化和 AI 处理，但只保存本地结果，最终显示“调试完成，未提交 CMS”。

开发者模式默认关闭，开关单独即时保存到 SQLite；保存成功后才显示为开启。保存失败保持原状态并显示原因，不顺带保存其他尚未确认的 AI 设置或保留天数。任务处理模式只影响之后新入队的任务，已有正常任务仍会创建 CMS 文章。页面右键规则则立即跟随当前已保存开关同步到所有业务窗口。调试仍调用 CMS FormatContent、分类查询和真实 AI；禁止的是最终 Article 创建，不是所有网络请求。

## 任务与历史

模式随任务入队固定。修改开关不改变排队或运行中的任务，失败重试仍使用原模式和已有检查点。关闭开关不会把调试完成记录转成正常任务，也不会自动补交。

去重按账号、规范化 URL、任务模式区分。同一模式内仍返回已有记录；从调试切回正常模式后，重新输入相同链接允许建立独立的正常任务。调试完成是明确终态，不显示 CMS 成功，不记录提交时间或 CMS 文章 ID，也不提供提交结果核对按钮。

迁移 0005 通过事务重建任务表的状态约束与模式索引，保留旧任务字段、原文关联及结果。旧任务和设置缺少 developerMode 时按关闭处理。调试完成记录参与现有保留期清理，已被草稿引用的原文仍受保护。

## Console 数据

每条事件包含 userId、jobId、attempt、timestamp、step、kind、data，失败可附带类型化 diagnostic（operation、causes、context）；按任务、尝试、步骤及时间分组，错误默认展开。入队事件的 attempt 是当前已执行次数，新任务为 0，worker 首次执行为 1。

输出入队设置、任务开始、来源导航/验证状态、各页 HTML、合并原文、HTML 清理、后台格式化、AI 提示词和业务响应（包括已截断、未完成的返回）、字段校验、整理纠正、本地分页及最终 payload。关闭开关、无模型、校验失败或检查点复用会显示原因；终态以 SQLite 记录为准。

仅调试任务输出详细业务数据，按事件所属账号核对当前登录账号。工作区切页继续监听，退出时释放；退出、失效、换号或工作区卸载时，清理已打印的本账号 Console 日志。正文作为 Console 数据，不插入页面 DOM；密码、CMS Token、AI Key、Cookie、认证头和凭据库读写不进入事件。日志不另建数据库表、不写文件或 localStorage，保留范围由本次 WebView Console 决定。

F12 只打开主窗口 DevTools，不负责切换关闭。命令由 Rust 复核窗口、会话和已保存开关，来源 WebView 无调用权限。日志发送或监听失败不改变后台采集结果。排队任务在被 worker 领取前取消，也会单独打印已持久化的最终状态。

## F12 开关即时保存修复

原先开发者开关只修改未保存表单，F12 命令读取 SQLite；因此界面已勾选时，后端仍可能按关闭处理。现在通过独立 `harvest_set_developer_mode` 命令原子更新这一项，保存成功后才更新勾选，过程中显示保存状态并防止并发提交；失败时保持原状态。其他 AI 设置和历史保留时间仍通过原保存按钮确认。

临时组件诊断复现原问题：`checked=true, persisted=false, f12Allowed=false`；修复后为 `true/true/true`。保存失败验证保持 `false/false/false`，其他未保存字段不会被一并提交。内存 SQLite 核对确认开关保留 JSON boolean 类型，标签设置和保留天数保持原值。诊断未操作真实 CMS/AI 或修改用户数据库，未新增仓库测试文件。

## 右键菜单

关闭开发者模式时，主窗口所有路由、登录页、弹窗与来源采集窗口均禁用右键菜单，包含输入框、图片、链接、空白处及内嵌页面。开启后恢复页面菜单；F12 仍受 Rust 的主窗口、登录会话和持久设置校验，来源网页无业务 IPC 或调试权限。DevTools 自身与操作系统菜单不受页面规则影响。

Rust 在读取 SQLite 设置后创建主窗口，通过每个文档的初始化脚本在页面脚本之前安装 contextmenu 捕获处理器。保存单独开关或完整设置都会同步当前窗口，导航和新建窗口再次同步。左键、文字选择及键盘复制粘贴不受影响。

## 失败诊断与采集窗口

Tauri 运行时创建 `about:blank` WebView 时跳过初始导航，单独等待加载完成不会触发文档就绪。现在在来源窗口创建、注册及生命周期监听安装完成后，显式导航到 `about:blank`；收到原生加载完成事件后，再执行带回调的 JavaScript 和文章导航。首次文档提交前，macOS Wry 只缓存脚本文本而丢弃回调，因此不能省略就绪等待。初始化等待上限仍为 30 秒。

初始化只发生在新建窗口时。已就绪窗口直接复用；初始化期间任务取消不会打断后台窗口创建，后续任务复用同一窗口和共享就绪状态。调试事件记录创建完成、空白页导航请求、加载开始、加载完成及等待耗时。初始化失败附带当前 URL、窗口是否存在及导航请求状态；程序主动清理会先打印“程序因初始化失败关闭窗口”，与用户关窗区分。

窗口真实销毁、回调中断但窗口仍存在、读取超时、JavaScript 异常与 JSON 解析失败分别报告。脚本在页面内统一捕获异常并返回名称、message、stack；导航读取暂时失败在原有等待期限内继续尝试，相同错误不连续刷屏，等待结束记录最后错误、累计次数、页码、URL、页面状态与耗时。等待人工验证时关窗也会结束该次采集，不再无限等待继续按钮。

CMS 与 AI 请求边界保留 HTTP 状态、业务返回体、错误链及解析原因。沿用 CMS 16 MiB、AI 2 MiB 的响应读取上限，超限或读取中断明确标注正文不完整。敏感字段及实际使用的密钥/令牌在生成诊断时脱敏；普通 IPC 仍只返回简短 code/message。AI 回退、正文纠正及分页失败记录详细原因与处理结果；业务失败先打印，再保存最终状态，状态保存失败另行输出。

## 手动删除记录

素材导入列表仍为标题、状态两列。已添加到 CMS、调试完成、失败、已取消、已中断记录提供删除按钮及确认弹窗。排队、运行、等待验证、等待登录不提供删除；提交结果待确认须先核对并标记，再删除。

操作沿用类型化 harvest_job_action 的 delete 动作。Rust 核对账号及任务结束情况，在事务内按允许状态删除任务和处理结果，仅清理没有草稿或其他任务引用的采集原文。删除不调用 CMS 删除接口；删除后该账号、链接和任务模式的去重限制解除，重新采集可能再次创建 CMS 文章。删除与重试并发时由 SQLite 状态条件决定结果，失败不移除列表记录。此调整不新增迁移或日志表。
