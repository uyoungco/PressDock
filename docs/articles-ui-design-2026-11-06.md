## 现状审查

现有界面的中性色、线性图标、独立列表滚动、保存锁和正文保护已有明确基础。此次按 Unslop 的轻度整理方式延续既有风格，重点重排密度、主次与编辑路径。

1. **列表信息被摊开。** 默认 14 个业务列合计 2510px，1440px 窗口中记录区约 1176px；标题与辅助字段并列，浏览要频繁横向移动。
2. **配图把行撑高。** 三张图各自占列，图片尺寸、体积另起两行；演示常规行约 143px，首屏只能完整看少量文章。
3. **低频筛选长期占位。** ID、作者、两个标记和日期全部展开，标题检索与搜索按钮分布在不同位置。
4. **字段名称混用。** 列表和表单直接暴露 TitlePic、Comment、Tags 等字段名；editor 的业务中文含义暂不明确，应保留原标记，避免误译。
5. **正文出现太晚。** 1440×900 下，桌面编辑器正文起点约 y=946；用户先看到三图上传、标签、摘要、作者和来源，首屏看不到正文。
6. **元数据纵向占用偏大。** 三组原生文件输入、宽分类与逐行来源等共同拉长表单；编辑正文与核对信息需要来回滚动。
7. **正文工具同一层级。** 高频格式、分页、源码、撤销和低频操作排成连续图标，收窄后缺少明确分组。
8. **助手控件纵向堆叠。** 配置提示、生成、插入、页码、上一页/下一页、定位和字数分散在预览之前，正文预览受挤压。
9. **页码缺少内容线索。** 现有按钮提供页号与字数，较多页面时仍要逐项点开确认内容。
10. **应用与保存需要持续区分。** 现有逻辑正确保留“生成 → 预览 → 应用 → 保存”；新布局应把这个边界放在状态与按钮上，而非增加重复说明。
11. **异常不能为密度让路。** 保护正文、嵌套分页、配置缺失和失败都具有实际约束，不能只留禁用按钮而删掉原因与处理入口。

## 五行方向

- **产品：** 新闻编辑核对图文、调整分页并保存 CMS 文章的工作空间。
- **性格：** 紧凑、审慎、专注。
- **场景：** 校样台；纸白内容区、中性灰工具区、校样蓝主操作。
- **重点：** 文章正文与逐页预览承载排版细节，工具和背景保持克制。
- **识别细节：** 带页码的分页校样线，在正文和助手预览中使用同一语汇。

不更换品牌、字体系统或全局导航；不增加营销插画。界面主按钮、选择与必要焦点使用校样蓝，错误与约束使用带文字的语义反馈。

## 列表：先看文章，再看辅助字段

默认四列为“新闻内容、配图、分发记录、操作”。新闻内容聚合标题、编号、分类、作者、分页数及本地新闻时间。完整标题与时间可悬停查看；标题仍打开文章或审核预览，编号保留同一打开能力。

配图三张并列，默认 72×40px，缺图使用小尺寸虚线占位；尺寸和体积移至预览或悬停信息，避免每行三套元信息挤占高度。常规行 72px，标题允许两行；额外字段与长分发说明允许必要增高。

分发区区分“推荐”与“分发位置”，不把两者相加冒充渠道数，更不将素材关联当作正式发布成功。常见状态简写为“已推荐 · 分发 2 处”，悬停或展开可查看全部推荐与渠道信息。

行内保留“编辑”和优质文章的“转素材”，完整名称在提示与表单中为“添加到渠道素材”。打开文章/来源等低频动作进入更多。稿件未增加删除、审核、优先审核等当前应用尚未提供的能力。

常用筛选包含标题、分类、起止日期；编号、作者、editor 和努比亚进入“更多筛选”，仍然点击搜索才提交。条件范围遵守原权限：作者与 editor 仅优质及一级，努比亚仅优质。暂不猜测 editor 的中文含义，实施前可按业务词汇表确认。

按工作区实际宽度适配侧栏：960px 起四列；640–959px 将分发摘要收回新闻内容副行，缩小三图与操作列；不足 640px 使用卡片，保留同一组信息和动作。用户额外显示的超宽列仅在记录区滚动，不能撑宽整页。

## 编辑：正文首屏可见，信息随时核对

桌面仍按需打开右侧编辑工作区，宽度不超过 1184px，距窗口边缘 16px；头部与保存栏固定。左侧为标题、正文工具栏、正文滚动区、字数和页数，右侧 300px 为文章信息。标题直接编辑，不额外增加重复标题预览。

文章信息依次组织分类/作者、摘要、标签、三张标题图及来源。分类与作者并排；缩略图、图片名称与更换动作同行，地址紧随其后，保留原图片上传和粘贴能力。主图、第二张图、第三张图使用中文标签；来源仍是现有 sourceUrl。

正文和信息各自滚动，外层不滚动。可收起文章信息，为正文增加宽度；宽度不超过 1100px 时切换“正文 / 文章信息”页签，正文编辑器继续挂载，选区、撤销栈、图片上传与两侧滚动位置须保留。

桌面常见格式、链接、图片、分页、撤销/重做和源码保持可达；低频动作在更多。窄屏常显正文样式、加粗、图片、分页助手和更多，其余操作在菜单中，触控不缩小到桌面图标尺寸。

正文排版使用 16px / 约 30px 行高，辅助信息 12px；编辑范围沿用原 HTML、图片尺寸和图注，不为了本稿样式重写正文。分页校样线为编辑装饰，绝不保存到 HTML。

保存按钮为“保存修改”；上传/保存期间显示原进度状态并锁定重复提交、关闭和相关正文操作。失败在固定底部附近反馈并保留完整输入。未保存状态明确显示“有未保存的修改”，不显示自动保存或云端已同步等未经支持的状态。

## 分页助手：页码目录与正文预览

桌面助手宽不超过 1040px，高约 640px，并受视口减 32px 约束。头部、状态条和底部固定；左侧 200px 页码目录，右侧预览。取消原先多排按钮与说明的堆叠，短页不再占用过大的弹框高度。

目录项包含页号、字数与页首文本；当前页用浅蓝底和细边线标识。目录较长时独立滚动。预览保留原正文排版，上一页/下一页、定位正文和分页操作固定在预览上方，正文区域独立滚动。页数、字数从现有分页模型推导，不新增持久字段。

“当前段落后分页”明确使用原正文光标所在内容块，不能误导为在当前预览页末尾插入。删除与上一页合并进入预览操作菜单；首尾、嵌套、上传、保存和初稿预览期间继续遵守现有权限。

| 状态           | 展示                                       | 操作与限制                                     |
| -------------- | ------------------------------------------ | ---------------------------------------------- |
| 当前分页       | 当前页数/字数、页码目录、原正文预览        | 不自动请求 AI；可查看、定位和允许的手动调整    |
| 正在生成       | “正在生成分页…”及取消生成                  | 不显示虚假百分比；保留当前分页，禁止冲突动作   |
| 未应用初稿     | “初稿预览”、前后页数、替换现有分页说明     | 主按钮“应用分页初稿”；可取消或关闭丢弃         |
| 已应用         | 回到当前分页，文章显示未保存               | 仍需“保存修改”写入 CMS；一次撤销可恢复         |
| 初稿失效       | 明确正文或标题变化，需要重新生成           | 应用禁用，不能把旧结果覆盖新正文               |
| 配置缺失       | 默认模板、页长参数或绑定模型缺失的具体原因 | 配置入口沿用现有设置；不在助手内增加模型选择器 |
| 失败/输出上限  | 原因、当前正文保留、可手动重试             | 不自动重发，不清空原有分页                     |
| 嵌套分页       | 原正文可预览，解释需先修正顶层结构         | 禁止生成、插入、删除、合并；保留允许的定位     |
| 不可拆内容超长 | 在初稿中保留核对提示                       | 图片/图注、列表、引用等继续按原算法保护        |

关闭按钮、Esc 和遮罩关闭助手并丢弃未应用初稿，保留已应用修改；仅关闭助手，不能误关外层文章。定位在焦点约束解除后回到正文，不创建历史，不写正文。

手机采用全屏，页码目录改为可横向滚动的紧凑页签，预览区滚动；生成、应用、取消和关闭始终可达。保留现有 Android 返回和不自动唤起输入法的策略。

高度不超过 520px 的手机视口进一步压缩助手：标题与生成放在同一行，页码目录隐藏首句，保留页号及字数；普通状态条减少重复说明，警告与错误仍完整显示。390×400 下预览区保留 122px，底部操作仍可达。

## 源码、链接、图片及转素材

**HTML 源码：** 采用与助手同宽的弹框，固定标题、提示与底部；中间由一个等宽字体文本区负责纵横滚动，避免“外层滚动条 + 文本框滚动条”竞争。保留原校验、保护模式只读、临时图片地址拒绝与整次撤销。“应用到正文”与“保存修改”分开命名；校验失败保留输入和错误，不关闭。

**链接：** 448px 小弹框，地址与显示文字纵排，底部按上下文显示移除、取消和应用。保留选区/书签和已有链接状态；关闭返回正文，中文输入与回车沿用原实现。原型的链接校验仅演示界面反馈，生产继续使用现有净化与协议逻辑。

**图片：** 预览按图片实际比例适配可用空间，图像主导内容区，不额外增加黑色占位。标题图与正文上传仍遵循 JPG/PNG/WebP、20 MiB、实际解码、上传锁和失败保留原图；预览不自动转存来源图片。标题图片未增加本地处理或新的 CMS 字段。

**转素材：** 560px 右侧抽屉，按“标题与摘要、配图、目标渠道、来源信息”组织。双图并排，渠道/子渠道各自完整一行；共享表单仅在该入口显式启用紧凑展示，不能更改其默认行为。继续使用文章快照、原文章 ID、`Publishdate` 和独立 `cms_add_article_to_promote`，不得改用普通新增素材协议。标题优化仍显式发起，应用候选只回填表单。

**未保存：** 桌面保持继续编辑或放弃；Android 保留继续、保留草稿并返回、放弃。保留范围为当前运行内存，不能显示成重启后仍有草稿。会话失效、重新登录、换号、退出以及旧请求丢弃继续复用原逻辑。

## 实施边界与建议顺序

1. 先改文章列表的局部密度、筛选组织和默认列组合。保留四类存储键、列 ID、显式显隐与列宽；聚合字段不丢失原列的可配置能力。
2. 将 EditorSheet 的布局分为固定框架、标题与正文、文章信息，给桌面增加可选展示模式。切换布局不得重建 RichTextEditor 或改变受保护正文的原始字节。
3. 单独重排 PaginationAssistant 的目录、预览与固定控件；继续依赖当前 ProseMirror 文档、默认模板、取消控制和原分页服务，不新增另一份正文状态。
4. 调整源码、链接和图片浮层的局部布局，统一焦点与滚动；转素材按入口启用现有共享表单展示模式，保留独立保存回调。
5. 回归正文保真、元数据保存、分页撤销/重做、图注绑定、候选失效、请求取消与迟到结果、锁定、未保存确认、会话和 Android。隔离验收继续拦截 CMS 写入。

不升级组件库，不引入新的编辑器、自动保存、页长滑块、批量审核、发布状态或数据库协议。全局导航、工作台、渠道列表与素材导入不在本稿变更范围内。

## Unslop 九步

间距以 4px 为步长，控件 32px、触控 40–44px、列表 72px；颜色沿用中性表面与校样蓝；图标为统一 16px 线性图标。文案区分应用与保存，字体保持现有系统界面体系，正文单独提高可读性。布局突出图文与分页，细节保留标题悬停、键盘焦点、错误和锁定。视觉素材来自演示文章，不生成装饰插画。动效仅保留短颜色反馈，支持减少动态效果。
