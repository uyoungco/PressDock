## 1. 结论与建议范围

可以迁移，但应迁移采集行为和业务规则，在 PressDock 的 React / Tauri / Rust 架构中重新实现。建议复用现有 CMS 登录、AI 提供商与模型配置、类型化 IPC 和 SQLite；不直接启动旧 CLI，也不复制其账号、密钥和 Python 打包流程。

需要先确认“爬虫功能”的范围。旧项目实际包含两部分：

- **采集本体**：识别来源、HTTP 或浏览器取页、正文提取、来源站分页合并。
- **采集后处理**：新闻后台格式化、AI 简介/标签/分类、可选 AI 排版和发布系统分页、提交新闻后台。

建议先交付“输入链接 → 真实采集 → 保留原始素材 → 创建独立本地草稿”的闭环。后处理能力按确认结果接入；涉及 HTML 的存储及编辑方式须在第一阶段一起确定，避免先丢掉图片，后面再补救。

如果你希望完整替代 ArticleHarvest，最终范围可以覆盖上述两部分，但“采集完成”“本地保存”“已提交新闻后台”“已正式发布”需要分别展示。

## 3. ArticleHarvest 的实际能力

### 3.1 当前执行流程

```text
后台登录
  → 选择普通 HTTP / Edge CDP / Chrome CDP
  → 选择 AI 自动分类（默认关闭）
  → 选择 AI 排版和分页（默认关闭）
  → 循环输入单个 URL
  → 根据域名匹配站点适配器
  → 抓取首屏及来源站后续分页，合并原文
  → 调用后台 FormatContent
  → AI 生成简介、分类、标签，逐字段合并
  → 可选 AI 排版 + 本地计算发布分页
  → 普通模式提交 Article；--dev 只输出最终 payload
```

`--dev` 仍会登录后台、访问来源、调用格式化和已启用的 AI；它只跳过文章提交，不是离线模式。[AH-1][AH-4]

### 3.2 能力清单

| 能力           | 当前实现                                                                              | 迁移判断                                       |
| -------------- | ------------------------------------------------------------------------------------- | ---------------------------------------------- |
| 站点支持       | 实际实现抓取的是百度适配器，映射 `baijiahao.baidu.com`、`mbd.baidu.com`               | 首批建议只承诺这两个入口                       |
| 其他适配器     | `site-a.com`、`site-b.com` 为不完整示例，没有实现 HTTP `fetch`                        | 不计为已支持真实网站，也不据此承诺通用网页采集 |
| 普通 HTTP      | 百度用 `curl-cffi` 的 `impersonate="chrome"`，最多尝试 3 次；没有显式请求超时         | 迁移时不能假定普通 reqwest 请求与其等效        |
| 浏览器采集     | 连接已运行的 Chrome / Edge，使用浏览器原有会话读取渲染后的 HTML                       | 行为可重实现，需要新增原生浏览器连接能力       |
| 标签页复用     | URL 忽略片段 `#`，保留全部查询参数；多匹配时让用户选择，没有匹配时创建标签页          | 建议保留                                       |
| 验证与登录     | 等待正文 30 秒，超时激活标签页并等待用户继续或取消                                    | 改为桌面任务提示和继续/取消操作                |
| 来源站分页     | 相对地址补全、访问去重、最多 30 页，拼接各页正文                                      | 保留，补全“不完整”判定                         |
| 标题/作者/时间 | 提取标题和作者；虽然有时间提取方法，但 `RawArticle` 和主流程不保存原站发布时间        | 时间若纳入属于新增字段，需要确认               |
| 后台格式化     | 清理 HTML 后调用 `/api/Util/FormatContent`，获取正文、简介和主图；对段落/图片追加换行 | 属于后处理，不是本地纯采集                     |
| AI 元数据      | 输入原始标题和原始正文纯文本；简介、分类、标签分别校验                                | 可复用规则，分类语义必须先核实                 |
| AI 排版和分页  | 模型输出原文片段/图片编号的布局，程序校验和渲染、计算分页                             | 当前为未跟踪模块；迁移复杂度明显高于简介/标签  |
| 提交后台       | 普通模式自动 `POST /api/Article`；开发模式展示同一份 payload                          | 桌面端建议改为明确的“提交后台”动作，等待确认   |
| 队列/并发      | 有 `QueueManager`、队列上限 100、并发数 5，但没有接入当前入口                         | 当前实际是单篇串行，批量/并发是新增能力        |
| 历史/恢复      | 主流程没有本地文章库、持久任务或断点恢复                                              | 不能声称迁移即可获得这些能力                   |
| 图片           | 提取正文 HTML 中的图片标签；客户端没有独立的本地下载、离线缓存和图片资源表            | 需确认链接保留、后台转存和离线要求             |

浏览器模式退出或取消时只释放调试连接，不关闭用户浏览器及标签页。调试连接绕过环境代理，页面本身按浏览器网络设置访问；普通 HTTP 模式是另一条请求路径。[AH-2][AH-3]

### 3.3 已有 AI 规则

**元数据规则**：[AH-5]

- 简介：去首尾空白后非空，最多 130 字符；超长则该字段无效，不截断。
- 标签：字符串数组，每项去首尾空白且不得为空，按原顺序去重后应为 3～5 个；某项无效或数量不符则整个标签字段无效。
- 分类：只接受固定集合中的整数；关闭自动分类时不采用 AI 分类。
- 单字段无效不影响其他合法字段；调用或整体解析失败则保留后台简介、默认分类和空标签。
- **实际默认分类为代码中写死的 `1`**。当前 `FormatContent` 映射不读取分类，因此“关闭后保留后台生成分类”的注释不能作为真实行为依据。
- 关闭自动分类不会关闭简介和标签生成；旧 CLI 没有单独的“关闭全部 AI 元数据”选项。

**可选排版规则**：[AH-6]

- 模型只返回文本片段、图片编号及连续语义组；程序引用原文渲染，校验遗漏、重复、文字顺序和图片顺序。
- 段落目标为 1～2 句、40～100 字；以语义组边界分页，每页目标 240 字，全文不超过 280 字时保持单页，尾页不足 100 字时尝试平衡或合并。语义组超长时可以超过页长目标。
- 图注与图片同页，不复制图片；来源行放在全文最后。
- 允许模型判断并删除连续位于首尾的独立文本块；不能删除中间正文。图注中的指定装饰符、图源尾注也会清理。**保真校验不代表绝不删字，现有规则明确允许这些删除。**
- 输出一个 HTML 字符串，以 `[!--empirenews.page--]` 分页，不产生多个文件。
- 完整响应结构或保真校验失败时最多请求纠正一次；网络失败、截断或再次失败则回退原后台排版。遇到表格、音视频等当前不支持的结构也回退。
- 旧实现对 DeepSeek 官方地址附加专用思考参数和输出额度；PressDock 当前通用生成接口没有同样的全部参数，不能承诺原样复制后兼容。

## 5. 实施前必须处理的差异

### 5.1 分类 ID 存在明确语义冲突

旧 AI 提示词和 2026-08-10 的历史后台契约使用相同 ID 集合，但名称含义不同，单靠整数白名单无法发现错误。例如：

| ID  | 当前 AI 提示词 | 历史后台契约记录 |
| --- | -------------- | ---------------- |
| 1   | 国内           | 社会             |
| 2   | 国际           | 娱乐             |
| 3   | 社会           | 军事             |
| 4   | 体育           | 财经             |
| 7   | 科技           | 奇闻             |
| 10  | 军事           | 体育             |
| 12  | 健康           | 科技             |

这意味着“AI 返回合法整数”仍可能分错类。本报告没有连接后台，**不能认定哪份名称表代表今天的真实分类**。[AH-5][AH-7]

建议在接入分类时读取并核对后台分类清单，由界面使用同一份 ID/名称数据生成 AI 约束；未核实前只保存本地结果，不启用自动分类提交。默认分类是否继续使用 `1` 也需要确认。

### 5.2 HTTP 抓取的网络行为不能直接等同替换

旧项目使用浏览器指纹模拟；PressDock 已有的是 reqwest 客户端。重写 HTML 解析可以实现同等提取规则，但无法仅凭源码保证相同的反爬通过率。

建议用你认可的代表链接验证两种采集模式。若原生 HTTP 成功率不满足要求，再决定优先浏览器模式还是引入额外 HTTP 能力；不预先加入 Python 运行时作为默认方案。浏览器模式也仍依赖站点适配器，不因此获得任意网站提取能力。

### 5.3 来源分页可能被静默截断

旧 `collect` 遇到后续 HTTP 页为空时直接停止并返回前面内容；达到 30 页、异常分页协议或循环也会停止，没有完整性结果。浏览器获取抛异常时则终止整篇，行为不完全一致。[AH-2]

此外，HTTP 路径只返回 HTML，没有向分页逻辑传递响应最终 URL；浏览器路径则会传递。因此 HTTP 重定向后的相对地址解析也需要修正。

建议记录停止原因、已采页数与是否完整。后续页失败或到达上限仍有下一页时，保留已采原文并明确警告，不自动按“完整采集”继续提交；循环分页标为异常，由用户核对。

### 5.4 原文 HTML 与安全展示需要分开

旧百度提取器会删除 `class`、`href`、`style`，其后还有激进 HTML 清理；这些规则可能丢失链接或结构。它们也不是完整的安全净化器，不适合直接作为桌面 HTML 渲染边界。[AH-2][AH-4]

建议保留一份不可编辑的“提取原文 HTML”，清理及格式化只产出草稿或预览。若增加图文预览，使用受控的标签/属性规则，去掉可执行脚本、事件属性和危险链接；不能直接把任意网页 HTML 注入应用界面。

### 5.5 提交后台不等于正式发布

旧客户端只以响应 `msg == "succ"` 判定提交成功，没有跟踪文章 ID 或正式发布状态。现有 PressDock 渠道素材的增删改也不代表文章创建接口已经接入。[AH-4][PD-4]

建议先显示“已提交后台”；仅在确认实际发布语义后设置“已发布”。提交超时或断线应显示“结果未确认”，不能自动重复创建文章。是否需要查重、核对远端 ID 和关联渠道素材须另外确认。

## 6. 建议的重实现方案

### 6.1 技术路线

| 方案                | 优点                                                     | 代价                                                                      | 建议                                 |
| ------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------------ |
| Rust 原生重实现     | 与现有分层、凭据、取消和数据库一致；无需额外 Python 进程 | 新增 HTML 解析及浏览器 WebSocket/CDP 能力；HTTP 指纹行为需验证            | 推荐                                 |
| 打包 Python sidecar | 更接近旧 curl-cffi/BeautifulSoup 运行行为                | 增加跨平台产物、进程通信、取消、错误及凭据传递成本；旧 CLI 不能直接当服务 | 仅在原生 HTTP 的实际限制明确后再评估 |

新增依赖的具体选型留到实施阶段验证；本报告没有安装依赖，也没有锁定未经验证的库或版本。

建议的数据流：

```text
素材导入页面
  → features/import 业务服务
  → 类型化采集 IPC
  → Rust 采集服务
      ├─ 来源匹配与网页获取（HTTP / 浏览器）
      ├─ 站点解析与来源分页合并
      └─ 原始素材 + 初始草稿，事务写入 SQLite

独立后处理动作（按确认范围接入）
  → CMS 格式化 → AI 元数据 / 排版 → 更新草稿

用户确认提交
  → CMS Article 创建 → 记录可确认的后台结果
```

组件仍不得直接使用 `invoke`、SQL、CDP 或远程 HTTP。来源网页使用独立客户端，不能携带新闻后台的令牌或 Cookie。新增 IPC 同步注册到 `lib.rs`、`build.rs` 和 capability，避免开放通用 HTTP 或任意 CDP 命令给前端。

浏览器连接可沿用旧规则：自动发现默认数据目录、手输目录/地址、只连接现有浏览器、重复 URL 选择标签页、验证后继续读取同一页、断线重连。建议首期只支持本机调试地址；远程 CDP 是否需要再确认。

模块可在现有 `features/import` 和 Rust 新增的 `harvest` 业务模块内组织，先做百度适配器，不建设动态插件系统或无调用者的抽象层。

### 6.2 数据与兼容

| 数据                | 建议处理                                                                                     |
| ------------------- | -------------------------------------------------------------------------------------------- |
| 输入 URL            | 原样保留作为来源追溯；不能删除 `id` 等有意义参数                                             |
| 最终 URL            | 另存，供重定向解释、相对链接解析及重复识别                                                   |
| 原始标题/作者       | 保留采集值；缺失作者为空，不保存 `No author found` 这类占位串                                |
| 原站发布时间        | 如果需要则解析并保留来源值；未知为空，不能用导入时间代替                                     |
| 原始正文            | 保留提取后的 HTML 与用于检索/AI 的文本；清理、AI 和保存草稿不得回写                          |
| 草稿正文            | 明确格式，使用一个可编辑的正文作为唯一依据；纯文本由 HTML 派生时不能再变成另一份独立编辑版本 |
| 简介/标签/分类/主图 | 若后处理或提交纳入范围，保存为草稿元数据；标签内部使用数组                                   |
| 采集记录            | 保留方式、适配器标识、采集时间、页数和完整性；任务历史是否落库由需求决定                     |
| CMS 结果            | 确认接口后保存远端文章 ID、提交状态和可核对结果；不推断发布成功                              |

现有 `content` 没有格式标记，建议通过新的 SQLx 迁移增加格式信息和必要字段；历史稿件标为纯文本，不猜测字符串是否是 HTML，也不修改已执行迁移。已有演示数据保留标识，真实采集设置 `isDemo=false`，编辑器中写死的“演示素材”需同步改为真实判定。

第一阶段不保存完整网页 DOM、浏览器存储或 Cookie；本文中的“原文”指站点正文提取结果，不承诺完整网页离线归档。若要离线图片、批量任务或恢复历史，再增加对应的存储，不预建无用途的表。

### 6.3 建议的交互和失败规则

| 场景                    | 建议默认行为                                                                    |
| ----------------------- | ------------------------------------------------------------------------------- |
| 不支持的域名            | 在请求前明确提示不支持，不创建看似成功的真实稿件                                |
| 抓不到标题或正文        | 不保存占位内容；提供重试，或在确实采到正文时允许手工补标题                      |
| 标题超过现有 200 字限制 | 保留原始标题，保存草稿前要求人工调整，不静默截断                                |
| 重复 URL                | 提示已有稿件，默认打开已有记录；重新采集创建新原文版本/新稿，不覆盖旧原文与草稿 |
| 来源站分页失败          | 保存已采素材并标记不完整；由用户决定是否用部分内容创建草稿，不自动提交          |
| HTTP 失败               | 限时结束；只对临时网络错误做有限 GET 重试，验证码/拒绝访问提示切换方式          |
| 需要网页验证            | 任务进入“等待用户”，用户完成验证后点继续；取消释放连接，不关闭标签页            |
| CMS 格式化失败          | 保留本地已采素材和草稿，单独显示后处理失败；不把网页采集也当作未发生            |
| AI 失败                 | 保留已有正文和元数据，显示警告；由用户决定重试，不自动重复付费调用              |
| AI 排版校验失败         | 回退处理前正文；是否允许额外一次纠正请求由你确认                                |
| 取消/离开页面           | 提供取消；若要求离页后台继续，任务需归属应用层；已完成的本地保存保留            |
| 退出账号/切换账号       | 中止后续远程动作，丢弃旧会话结果；不删除已存原文                                |
| 提交后台超时            | 记录“结果未确认”，提示核对，不自动重发                                          |

建议 URL 去重规则仅忽略片段并做 URL 标准化，保留查询参数；已知重定向别名可以辅助去重。不同 URL 指向相同正文的识别不作为默认新增功能。

建议来源请求仅访问确认支持的站点；重定向及分页目标也检查支持范围，百度两个入口间的合法跳转需允许。页面设置明确的超时和 HTML 大小限制，数值在确认表中决定。远程内容只在真实输入边界校验，不在内部堆叠无意义的防御层。

### 6.4 AI 与图片的接入边界

**AI：**复用 PressDock 提供商、模型、安全密钥和取消能力，新增元数据/排版任务的提示词及输出校验。现有标题模板的候选数、标题字数和唯一默认项不适合直接套用；若要求可编辑模板，应按任务类型设置各自的默认模板，不影响现有标题优化。

元数据读取原文还是当前编辑草稿，也需要确认。建议首次采集使用原文，编辑页手动重新生成则使用当前草稿，并在界面说明输入范围。AI 标题优化继续由已有按钮触发，不因为采集完成就自动改标题。

**图片：**建议首期保留来源图片引用和顺序，补全相对地址及实际需要的懒加载属性；缺失图片提供可见提示。是否下载、离线保存、转存 CMS、选择主图、应用渠道图片预设分别确认。`FormatContent` 服务端是否转存图片，不能从客户端代码证明，需后续核验；不能直接认定格式化完成就已拥有图片副本。

采集图片预览如需请求，应登记本次稿件内的图片来源并使用独立无 CMS 令牌的加载路径，不能直接放宽现有渠道图片许可集合。既有本地图片处理与上传只在明确的图片操作中复用。
