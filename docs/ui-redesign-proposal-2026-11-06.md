# PressDock UI 改版方案：编辑调度台

日期：2026-11-06。交付性质：调研与设计提案，尚未修改业务界面。

评审修订：渠道编排取消常驻“选中素材 / 内容检查”面板，表格使用完整内容宽度；整体采用紧凑密度，压缩页头、工具栏、导航及行间距，正文仍保持阅读行距。

## 结论

建议重构 PressDock 的工作空间：**以正在处理的新闻为中心，把采集队列、正文编辑和渠道编排接成一条可追踪的操作路径。**

改动集中在三个地方：工作台从演示统计改成真实任务入口；文章从长表单侧栏改成完整编辑台；渠道素材从字段表改成标题、配图、位置优先的编排工作面。保留现有功能、审核类别和业务协议，调整导航分组、信息层级和页面布局。

视觉主张为“纸白、墨黑、校样蓝”。保留 PressDock 名称、报纸图形、Geist 与中文系统字体，界面以低饱和中性色为主，精细的中文稿件排版和分页刻度承担产品识别度。浅色优先用于阅读和校稿，深色提供同等完整的体验。

## 3. 五行设计方向

- **产品：** 帮助新闻编辑把来源文章整理成 CMS 稿件，再适配到渠道素材位的桌面工作空间
- **性格：** 专注、利落、可核对
- **世界：** 编辑部的稿纸、墨迹、校样与版面；外壳保持中性，校样蓝只用于当前操作与定位
- **重点：** 精心排版的正文画布，以及能同时核对标题、双图和位置的渠道编排面
- **签名：** 细蓝色“校样刻度”，只出现在当前分页位置、当前选中的稿件或正在检查的版位

这份方向是待评审提案。下一阶段实现前应按本方向统一组件和布局，避免逐页各换一种风格。

## 4. 信息架构：四个主工作区，两个辅助工具

建议侧栏分组：

```text
PressDock

编辑工作
  工作台
  素材采集
  文章库
  渠道编排

工具
  图片处理
  设置

历史演示稿件   ← 保留旧发布页与本地演示入口，降级为低频入口
账号
```

入口可以重排，已有 URL 继续可达，旧导航地址保留跳转。`素材采集` 对应现有素材导入，`文章库` 对应文章管理，`渠道编排` 对应渠道素材管理。

文章页内保留“优质文章 / 一级待审核 / 二级待审核 / 三级待审核”。它们是四种真实 CMS 查询类别，**不能擅自合并成“待编辑 / 审核中 / 已发布”流水线，也不增加拖动修改审核状态的行为。**

“发布管理”当前仍有演示边界，暂不作为顶级生产入口。名称与位置的改动需要同步空态说明、旧链接和用户习惯；真正的发布模块只在发布结果可验证后再定义。

## 5. 三个核心页面，整体重做

### 5.1 工作台：当天的任务调度，而非统计展示

首屏结构：

1. 页头：“工作台 · 11 月 6 日”，右侧唯一主操作“采集链接”
2. 紧凑计数：排队 / 处理中 / 需处理 / 已添加 CMS，全部说明统计范围和更新时间
3. 主区约 2/3：采集任务列表；需处理项在所选视图优先呈现，原有队列执行顺序不变
4. 辅区约 1/3：选中任务的阻塞原因、来源、下一步及 CMS 关联信息
5. 历史演示稿件单独作为低频入口，不参与生产统计

每条任务以标题为主，来源域名、时间、实际任务状态为辅。只出现一项当前可执行操作，例如“继续验证”“核对提交结果”“重试”。其他操作放到更多菜单。完成记录有可靠文章 ID 才显示“打开 CMS 稿件”；缺少 ID 时显示“核对 CMS 记录”，不根据相似标题自动关联。

计数优先来自真实采集记录。首版只做有数据支撑的计数，不能从本地演示文章推导“待编辑”“今日发布量”。若数据源尚未接通，页面明确展示“尚无真实任务数据”与采集入口，设计预览中的计数不进入正式环境。

### 5.2 稿件编辑：正文居中，属性靠边

桌面展开为完整工作面，替换当前以长表单为核心的编辑侧栏：

```text
返回文章库     稿件标题 / 未提交修改      预览     保存修改到 CMS
────────────────────────────────────────────────────────────
页面导航        正文画布                      属性检查器
第 1 页         标题                         基本信息
第 2 页         导语、段落、配图              文章图片
第 3 页         ── 分页刻度 ──               分类、作者、标签
                正文                         摘要、来源
                                             分页助手入口
```

- 1440px 级桌面采用 176px 页导航、正文至少 640px、288px 属性区；编辑模式可收起全局导航。正文推荐宽 680–760px，长文不会铺满整块屏幕。
- 1200px 以下先将页导航变成弹出目录；1000px 以下属性区变成右侧可开合面板，正文保持可读宽度。
- 标题、正文先出现。作者、分类、标签、来源等在属性区分组。三张文章图保留并明确用途，链接字段放到对应图片的展开信息中。
- 正文使用 17px/30px 或用户可调字号；标题 28px/40px、500。编辑中的正文以无衬线保证稳定，阅读预览可选系统宋体，避免下载大体积中文字体。
- 分页助手复用已有生成、预览、应用和一次撤销能力；主编辑画布显示轻量分页刻度与页导航。嵌套分页、纯图片、超长不可拆块沿用真实限制。
- AI 标题候选保持“生成 → 人工采用 → 未保存”，结果使用并列候选列表；不能因为采用候选就显示已保存。
- 图片处理在当前编辑上下文打开，完成后返回原图字段或正文插入点。图片原图、编辑结果和渠道图保持独立。

保存状态必须具体：“有未提交修改”“正在保存到 CMS”“CMS 保存成功 / 失败”。文章本地持久草稿恢复尚需额外实现，不能提前显示“已自动保存到本机”。后续若实现，必须把本地保存与 CMS 保存分别标注。

文章库继续使用现有服务查询、分类过滤、服务端分页及按类别隔离的缓存；进入编辑前记录筛选、页码和滚动位置，返回后恢复。

### 5.3 渠道编排：一眼看到新闻与目标位置

默认视图由“横向字段大表”改成“内容优先的编排表”。保留可切回的完整字段视图，满足核对原始信息的需求。

页头仅保留标题、开始排序及新增操作；渠道、子渠道、日期、结果数、刷新和列配置合并到一条紧凑工具栏，窄窗按需换行。按渠道配置选择上下文后，同值不再在每行大幅重复。

默认列建议：

| 列         | 宽度起点      | 规则                                                       |
| ---------- | ------------- | ---------------------------------------------------------- |
| 当前页位置 | 48px          | 编排时显示拖动手柄与位置；键盘上移/下移始终可达            |
| 新闻内容   | 320px，可伸展 | 标题最多两行；下方显示作者及文章编号。固定在左侧           |
| 主图       | 136px         | 80×36px 缩略图；实际尺寸、格式、体积在其下，读取失败可重试 |
| 第二张图片 | 136px         | 独立字段、独立实际指标；无图显示“未设置”                   |
| 更新信息   | 120px         | 若接口存在可靠值则显示，否则明确“未提供”                   |
| 操作       | 96px          | 编辑为主，详情/复制/删除在更多菜单；固定右侧               |

默认即为紧凑密度：双图行高约 72px，缩略图 80×36px，下方用 12px 字号展示实际指标；纯文字模式 48–56px。长标题可以增加必要行高，正文和辅助信息保持可读。图片放大与完整字段通过点击图片或详情操作按需打开，不常驻显示选中素材。

宽度不足时先移走更新信息与次要元数据，再将图片详情放入按需打开的弹层；标题与主操作始终可见。完整字段视图继续支持横向滚动、列显隐、列宽调整及偏好恢复，迁移时保留用户已有偏好并允许显式恢复新默认。

渠道列表使用完整内容宽度，取消“选中素材 / 内容检查”常驻面板；不因选中一行缩窄整个列表。用户点击编辑后再打开素材表单，点击图片或详情后再查看完整内容。若以后增加线上模板预览，需要另行核实模板，并说明准确性边界。

排序进入独立模式：上下文锁定，显示“仅调整当前页”；底部固定“取消 / 保存当前页顺序”，离开或换筛选时处理未保存顺序。保留现有拖动与上移/下移，不增加跨页排序承诺。

素材编辑侧栏宽 480–560px，按“标题与摘要 / 主图与第二张图 / 目标渠道 / 链接与来源 / 高级信息”分组，取代所有字段等权的纵向表单。标题计数可以直接做；渠道字数上限只在有真实配置时显示，未配置不猜测。

### 重点补全的状态

- 首次进入：提示配置什么、下一步去哪，禁止演示任务默认混入真实列表
- 初次加载：按最终列表结构显示骨架；刷新保留旧列表与原滚动位置，标明“正在刷新”
- 空结果：区分无内容与筛选无匹配；后者提供“清除筛选”，保留当前查询解释
- 错误：就地显示失败原因与重试，不只依赖短暂 Toast；失败保留表单和已载入内容
- 登录失效：保留运行内编辑缓冲，提示重新登录；不能承诺尚不存在的跨进程草稿恢复
- 提交结果待确认：明确要求核对 CMS；不提供会重复提交的无条件“再试一次”
- 删除：写清删除对象和后果；删除采集记录不等同删除 CMS 文章
- 图片未知：加载失败、读取不到指标和未配置规格均使用“待检查”，不能标为通过

### 状态用词的统一底线

| 实际事件               | 界面用词                         |
| ---------------------- | -------------------------------- |
| 链接已持久化到任务队列 | 已加入采集队列                   |
| 采集创建文章成功       | 已添加到 CMS                     |
| 编辑接口确认保存       | 已保存到 CMS                     |
| 渠道素材接口确认保存   | 渠道素材已保存                   |
| 请求发出但结果不确定   | 提交结果待确认                   |
| 无真实发布核验         | 不显示正式“已发布”               |
| 演示稿件历史状态       | 已发布（演示），仅在演示区域出现 |

## 7. 视觉系统与 unslop 九遍执行顺序

### 7.1 间距

4px 网格；页边距 16–20px，分组内 4/8px，组间 12–16px。页头 44–48px，侧栏约 200px，可收为 56–64px；导航行 32px、行间 4px。桌面按钮 32px，触控区正式实现时至少 44px。统一表格表头 32px、普通行 48–56px、双图行约 72px。减少结构性空白，不通过缩小正文字号压缩阅读内容。

### 7.2 色彩

| 语义        | 浅色      | 深色      |
| ----------- | --------- | --------- |
| 页面底      | `#F7F8F9` | `#111214` |
| 正文/面板   | `#FFFFFF` | `#191B1F` |
| 悬停/选中底 | `#F0F2F5` | `#23262C` |
| 主文字      | `#20242B` | `#ECEEF2` |
| 次文字      | `#525B68` | `#ADB5C2` |
| 辅助文字    | `#657080` | `#939DAD` |
| 细边框      | `#E2E5E9` | `#30343C` |
| 校样蓝      | `#2457D6` | `#93B4FF` |

浅色主按钮用校样蓝配白字；深色主按钮用近白配深色字，蓝色留给定位。白字在 `#2457D6` 上约 6.2:1，最终以实际渲染及状态组合复核。红/黄/绿只表达错误、阻塞和确认结果；蓝色不同时承担成功语义。选中行用灰色台阶加 2px 蓝色刻度，避免整片蓝底。

### 7.3 图标

延用 Lucide。导航/工具统一 16px、1.5 描边；单一文字色。AI 操作使用文字“标题优化”“分页助手”，不用星光表达不清楚的动作。状态保留文字，不靠颜色辨识。

### 7.4 文案

`Title` → 渠道标题；`TitlePic` → 主图；`TitlePic2` → 第二张图片；`SmallText` → 摘要；`LandUrl` → 落地链接。`保存`按目标区分为“保存修改到 CMS”“保存渠道素材”“保存当前页顺序”。移除“让新闻编辑更有条理”等首屏口号，用当前日期、范围与任务事实代替。

### 7.5 字体

界面继续 Geist Variable + PingFang SC / Microsoft YaHei / 系统字体。界面正文 14/20px、辅助 12/18px、列表标题 14/22px、页标题 24/32px。常规 400、交互标签 500、极少数结构标题 600。中文不加宽字距，不使用 10px 小标签；数字使用 tabular-nums，取消两位补零。

### 7.6 布局

移除“页面卡片里再嵌表格卡片”的双边框。主区铺满可用宽度，正文编辑按阅读宽度约束。结构按任务产生差异：采集是队列，文章是编辑画布，渠道是编排表，设置是分组表单。不会所有页面都套相同的卡片网格。

### 7.7 细节

按钮/输入圆角 8px，浮层 12px，内容画布直边或 8px。计数为普通文字，快捷键为小键帽。表头与操作区固定；检查器关闭后焦点回到原行。外链明确为打开来源；“详情”不会意外打开来源。危险操作进入明确菜单或确认层。

### 7.8 视觉内容

不生成宣传插画。文章标题、段落、图片和分页标记就是视觉素材。渠道检查区域能同时看到两种真实配图与标题换行，形成 PressDock 特有的内容重点。生产图片保持真实；设计预览使用标识明确的演示内容。

### 7.9 动效

悬停/按下 140ms，菜单 180ms，检查器进入 220ms；统一 `cubic-bezier(.22,1,.36,1)`。只过渡颜色、透明度与小幅位移。采集处理中旋转图标保留实际意义；不做循环呼吸或每行飞入。遵循 reduced-motion，排序具有键盘替代路径。

## 8. 桌面、窄窗与移动端

- ≥1360px：渠道页面为侧栏 + 全宽列表，不设置选中素材面板；工作台可展示任务详情，编辑器保留稿件属性区并可折叠全局导航
- 1024–1359px：列表铺满；检查器按需覆盖或替换右侧区域，不永久挤压标题
- 768–1023px：侧栏收起；筛选抽屉；正文优先；元信息通过检查器查看
- <768px：主列表用纵向内容行；稿件以“正文 / 属性 / 分页”切换；返回位置与未提交提示保留
- Android 延续现有功能可用性，不因为桌面重排而开放当前不可用的工作台、发布或外部 CDP 功能
- 校验 1440×900、1280×800、1024×768、390×844、360×640；正文和关键操作不能依赖整页横向滚动

## 9. 分期实施：先解决标题看不见，再贯通编辑生产

| 阶段                 | 交付与涉及文件                                                                                                          | 能力边界                                                                       | 验收重点                                                                   |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| P0-A：外壳与内容层级 | `DesktopLayout`、`TopBar`、`navigation`、`globals.css`；渠道 `table-model` / `MaterialTable` / `MaterialForm`；文章列表 | 以布局、默认列、文案、密度和焦点行为为主；已有用户列偏好需要明确迁移策略       | 标题、图片入口和编辑操作在窄窗可达；筛选、缓存、列宽、拖动、键盘功能保留   |
| P0-B：编辑台         | `EditorSheet`、`RichTextEditor`、`PaginationAssistant`、文章 actions/state/router                                       | 复用现有读取、保存、上传和 AI 服务；先做好正文/属性布局与上下文返回            | 正文无需经过长属性表；分页应用和撤销有效；上传失败与保存失败不丢失当前修改 |
| P1：真实任务调度     | `Dashboard`、`Import`、query-runtime、采集服务                                                                          | 新增跨页状态汇总、可靠 CMS ID 跳转等只读服务组合；需要核实返回字段，不虚构接口 | 真实与演示分离；统计范围可解释；待确认任务不能误重发；无 ID 不误关联       |
| P1：本地恢复         | 文章持久草稿服务、类型化 IPC、Rust、SQLx 迁移                                                                           | 独立功能建设，不能只改 UI 冒充自动保存；按账号、文章、版本隔离                 | 原始素材不被覆盖；换号隔离；恢复与 CMS 新版本冲突有提示                    |
| P2：经验证再做       | 保存视图、批量粘贴、真实模板近似预览、多渠道适配                                                                        | 先确认使用频率、接口字段及模板规则                                             | 真实任务试用后决定，不作为本次视觉改版前置条件                             |

建议首批以“渠道编排 + 编辑台”为主：这两个工作面直接影响每条新闻的日常操作。工作台可先做文案和演示入口收敛，等真实数据汇总就绪再替换主内容，避免上线一个漂亮但统计不真实的页面。

界面组件只调用业务服务，继续遵循 UI → 业务服务 → 类型化 IPC → Rust → SQLx；不在组件里添加 invoke 或 SQL，不用 localStorage 持久化正文、任务或密钥。原稿与草稿独立。新增设置先使用现有配置机制，避免另起一套存储。

## 10. 验收与评审标准

1. 在 1280px 窗宽的新默认布局下，无需横向滚动即可识别新闻标题并进入编辑；完整字段视图仍可访问全部字段
2. 从文章库进入编辑后，标题与正文首段在首屏；返回保持类别、筛选、页码和滚动位置
3. 未提交修改、本地草稿（实现后）、CMS 保存与渠道保存有清楚且不同的反馈；不会出现无依据的正式发布成功
4. 采集失败、待验证、提交待确认各有正确的下一步；刷新保留内容，错误不静默消失
5. 渠道排序明确仅当前页；拖动、键盘上移下移、取消与提交均保留
6. 所有设计预览及测试素材有演示标识；真实验收拦截写请求，不改线上素材
7. 正文、辅助文字、按钮各状态对比度达到所需标准；键盘焦点可见；窄窗与移动端没有关键控件遮挡
8. 发布实现前完成 README 中适用的 lint、前端测试、独立脚本测试、build、format、Rust fmt/test/clippy；涉及原生行为还要做 Tauri 验证。此次仅提交设计文档与静态提案，不把浏览器预览称为业务验收

建议用真实日常任务做改版前后对照：定位同一条稿件、修改一段正文并核对分页、从文章进入渠道适配、核对并保存当前页顺序。记录耗时、页面跳转、误点和未保存修改恢复情况，先采样再设量化目标，不提前承诺效率百分比。
