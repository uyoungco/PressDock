# AI 正文内容整理实施与评测

日期：2026-11-10。冻结提示词：[V6](prompts/v6.txt)，输出契约版本 2。原计划见[计划文档](../ai-body-organization-plan-2026-11-10.md)。

## 使用

1. 在“系统设置 → 提示词模板 → 正文整理”打开内置“正文整理提示词”，绑定已配置模型并保存。该用途有独立默认项，变量为 `{{title}}`、`{{blocks}}`。
2. 在“采集与 AI 处理 → AI 处理规则”开启“正文内容整理”。默认关闭；与“AI 自动分页”分别控制。修改自动保存，入队固定设置、提示词、模型与凭据引用。
3. 流程为采集原文 → CMS 格式化 → 元数据处理 → 正文整理 → 原有分页 → prepared。生产最多一次整理请求，无安全候选时不请求；输出不合法、截断或超时则保留整理前排版并记录警告。取消、换号和存储错误仍停止任务。

原文、格式化输入、整理检查点和最终草稿分别保存。已完成检查点在输入和版本一致时复用，避免重试重复付费。内置模板未预绑模型，缺配置时新任务明确提示配置入口。

完整指标和指纹见 [evaluation-summary.json](evaluation-summary.json)。全部 20 篇 A（采集/清理）→B（格式化）文字顺序一致。B→C（CMS 成稿）主要表现为长段拆分、样式造成的碎段合并、图注位置变化及分页。`11663855、11663841、11663829、11661245` 存在正文版本差异，不把 C 当作逐字正确答案；它们仍参与模型对 B 的保真验证。

样本 `11665072` 的百度/格式化正文有 8 张图、CMS 有 6 张。实际查看发现差额包含视频封面卡和消息截图，不能当作重复图自动删除；`11663830` 成稿反而新增了图片。首版因此保留全部输入图片及其位置。无明确图注 class 的说明和小标题可能同样没有句末标点，不能仅凭“缺少句号”决定合并。

## 六轮真实模型迭代

使用本机已保存的 `deepseek-flash / Responses` 配置及原生凭据库；未新建 AI 接口，未复制密钥。所有轮次均保存实际响应、计量、本地应用结果和拒绝记录。

| 版本 | 开发集结构校验 | 发现与处理                                                                                                                               |
| ---- | -------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| V1   | 8/8            | 模型返回拆分和图片组合移动编号，尚不能处理碎段；图片缺少画面信息，移动建议依据有限。                                                     |
| V2   | 5/8            | 增加合并要求后，出现冲突或无法安全映射的操作，严格拒绝。                                                                                 |
| V3   | 2/8            | 提示词要求模型同时计算段长和操作关系，仍不稳定，保留失败。                                                                               |
| V4   | 8/8            | 改为本地生成完整、互不冲突的候选，AI 仅选择 ID；留出阶段出现错误 `type` 字段。另修正评测器，使无候选时与生产一样跳过请求，旧失败不覆盖。 |
| V5   | 12/12          | 强调输出必须包含 `version`。自动保真通过，但逐段复核发现无标点图注/小标题仍可能被接入正文，因此未采用。                                  |
| V6   | 16/16          | 本地合并仅允许可见续句标点边界，提示词明确保护人物说明和小标题。无充分依据的词内碎段保留。                                               |

V1–V6 共 104 次真实请求，接口累计报告输入 342293 token、输出 4767 token，包含失败和复跑；接口未提供费用金额，未按假定价格估算。每轮细分及耗时见 JSON。开发迭代不会进入生产自动循环。

V6 最终结果：

| 集合                 | 工作流通过 | 真实请求 | 本地跳过 |
| -------------------- | ---------- | -------- | -------- |
| 开发 16 篇           | 16/16      | 11       | 5        |
| 新留出 4 篇          | 4/4        | 3        | 1        |
| 截图 4 篇各复跑 3 次 | 12/12      | 6        | 6        |
| 独立演示边界         | 4/4        | 2        | 2        |

20 篇逐篇文字与叙述顺序相同，96 张图片的属性与顺序相同。文字统计排除排版空白、零宽字符和分页标记，不表示 HTML 字节完全一致。超过 160 字的段落从 42 段降至 14 段；`11665072` 最长段由 857 字降为 150 字。完整引语、单个长句等可能保持长段，160 不是强制上限。合并完整续句也可能增加单段长度，不以“段落越短越好”评分。V6 对截图复跑的编辑选择仍可能波动，保真约束不变。

生产只接受 `{"version":2,"actions":["A1"]}`；不接受模型正文、HTML、未知/重复编号或其他字段。本地按原始节点片段重建 HTML。分页符、小标题、引用、列表和来源构成受保护边界；复杂结构不能映射时整步回退。
