## 依据与审计

以当前 Android 分支的 React 页面为依据，通过 ego-browser 在隔离演示入口查看渠道、文章、采集与设置。素材草稿读取在浏览器内替换为空值，避免旧演示 fixture 的缺失命令遮挡页面；未操作手机上的真实草稿。现状截图位于交付目录中的 `before-*.png`。

按 unslop 的检查项判断，本项目属于轻度优化：现有中性色、Lucide、侧边导航与业务层级值得保留，没有发现紫色渐变、发光、装饰 emoji、营销式宣称或无意义循环动画。主要问题如下。

| 位置       | 问题                                                   | 设计处理                                                     |
| ---------- | ------------------------------------------------------ | ------------------------------------------------------------ |
| 手机顶栏   | 长账号昵称与主题按钮占据固定空间，多个操作权重接近     | 保留 48px 顶栏；账号、外观集中在导航底部                     |
| 渠道素材   | 标题、重复渠道日期、编辑与删除抢占同一区域             | 筛选摘要集中展示；保留双图；编辑显式，删除进入更多菜单       |
| 文章卡片   | 图像体积、尺寸和长时间串常驻；大卡片边框与多层容器占位 | 平面列表以标题、缩略图、分类、作者和时间为主；完整规格在详情 |
| 文章正文   | 元信息与工具易争用屏幕；各层操作缺少统一节奏           | 基本信息 / 正文常驻页签，低频工具收纳，底部保存固定          |
| 素材导入   | 顶栏与内容重复标题；每条记录的状态、说明、动作松散     | 去除重复页头，输入与日期紧邻；记录形成连续列表               |
| 状态提示   | 等待验证、失败和待确认都容易被看成一般“处理中”         | 语义色与明确下一步配合，始终保留提交结果待确认的边界         |

## 五行方向

- **产品：** 帮助新闻编辑在手机上采集来源文章、校对 CMS 稿件并维护渠道素材。
- **性格：** 专注、利落、可核对。
- **世界：** 稿纸、墨迹、校样与版面；界面保持中性，校样蓝只标识当前操作。
- **重点：** 标题与双图构成的新闻阅读单元，以及正文与分页边界。
- **签名：** 细蓝色校样刻度，仅用于当前素材与正文分页定位。

这是既有“纸白、墨黑、校样蓝”方向的手机端细化。保留侧边导航，不增加常驻底栏；保留 CMS 四类文章，不改成新的审核流程。设计稿用于评审方向，之后实施需要以实际组件、原生安全区和业务状态为准。

## 九轮处理

1. **间距：** 以 4px 为主网格，局部 2px 微调；页边距 16px，正文 20px，组间 16–24px。导航与主要触控区域 44px，顶栏 48px。行内操作使用完整热区，即使图标只有 18px。
2. **颜色：** 浅色使用白色内容面与灰色设置背景，深色使用灰阶表面。强调色 `#2457d6`，深色对应 `#a7c0ff`；成功与需处理状态分别使用克制的绿与棕色，不把创建 CMS 文章表示成发布成功。
3. **图标：** 统一 Lucide 18px / 1.5 描边，跟随文本角色；取消装饰性彩色图标背景，保留有含义的素材、编辑、来源与裁剪图标。
4. **文案：** 页头只命名当前上下文；“修改尚未提交”“提交结果待确认”“保持应用前台运行”说明真实边界。按钮缩短，但保留“转渠道素材”“验证完成，继续”等业务含义。
5. **字体：** 延续 Geist 的拉丁字符和数字，设计预览补充 Noto Sans SC 中文子集，避免不同机器回退成不同字形。正文 16px / 约 30px，列表标题 15px / 23–24px，辅助文字 12px / 20px，权重 400 / 500，少量强调不超过 600。
6. **布局：** 保持现有工作区与功能顺序。标题与缩略图在同一阅读单元；筛选和编辑全屏；长列表、正文与参数区域各自滚动，固定操作留在底部。
7. **细节：** 按钮 8px、卡片 12px 圆角，边界使用细线。数字使用等宽数字特性；页码不补零。可见焦点环与原生 dialog 的焦点约束支持键盘操作。
8. **视觉：** 色彩集中在新闻配图与校样刻度，界面不增加 hero、机器人、装饰图表或背景材质。本地街区插画为明确标记的演示配图，用于观察版面，不是实际新闻照片，图片规格也是演示值。本次无需生成营销图片，没有图像生成提示词。
9. **动效：** 仅保留颜色与轻微透明度 / 位移反馈，使用同一 ease-out 曲线与 140–160ms 时长；支持减少动态效果。没有循环动画、布局尺寸动画或卡片缩放。

## 页面与交互说明

- **渠道素材：** 页面级筛选摘要；双图保留；编辑直接可达；删除须进入二级操作。排序时显示上下移和提交 / 取消。渠道切换清空子渠道，取消筛选不应用，明确点击后才更新摘要。
- **文章管理：** 四种类别从标题旁选择；每条保留编辑、转素材、更多信息。分类不等于审核状态，不提供拖动改审核类别。
- **文章编辑：** 正文展示与基本信息分开，预览切页签保留正文输入；低频工具收在更多菜单，分页建议与源码独立全屏。底部保存始终可见。独立“正文编辑”设计屏选中正文页签，用于评审阅读效果，不表示已经更改正式应用的默认页签。
- **素材导入：** 保留前台执行边界、取消、验证继续、失败重试与提交结果核对。已添加 CMS 的样例明确标为演示记录；任何按钮都不会制造真实采集或发布成功。
- **图片处理：** 画布与锁定参数分开，输出规格与最终编码结果区分；返回恢复来源表单。画布为布局示意，不在浏览器实现实际裁剪、编码或上传。
- **系统设置：** 七个既有分项按原有次序保留。提供商、模型和模板进入各自编辑；预览密钥字段为空，输入不保存。主题仅在本预览中切换。

## 业务边界与后续实施

原型使用内存演示数据，没有接入 invoke、SQL、CMS、采集网页或 AI。正文、素材、配置和密钥均不写 localStorage，也不代表原生草稿已经保存。保存按钮只显示演示说明，不发送任何业务请求。

后续应用时继续遵守 UI → 业务服务 → 类型化 IPC → Rust → SQLx；复用既有取消、草稿、会话隔离、图片处理与提交结果待确认逻辑。列表缩略图隐藏的尺寸与体积仍需在详情可达，不能从业务能力中删除。

浏览器预览不替代真机的安全区、系统返回、键盘、触摸裁剪或 Keystore 验收。这一轮不重新构建或安装 APK。

## 校验记录

通过 ego-browser 检查七个页面的 35 个尺寸与主题组合：360×640、390×400、844×390、390×844 深色、390×844 浅色。页面与固定区域无横向溢出；主要按钮和输入触控高度至少 44px，底部操作未超出视口，中文字体已加载。

18 项基础检查通过，覆盖渠道 / 子渠道依赖、筛选取消与应用、排序移动、导航与 Escape 返回、四类文章、正文页签输入保留、分页操作、七项设置、开关与空密钥输入。详细结果见 `layout-final.json`、`interaction-checks.json`；补充的取消排序、图片返回和离线导出检查见 `delivery-checks.json`。
