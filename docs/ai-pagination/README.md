# CMS 优质文章分页调研与 DeepSeek 实测

2026-10-30，使用 ego-browser 阅读 [优质文章列表](https://newsadmin.nccontrol.com.cn/index.html#/article/article-review-quality)。推荐采用 [第 9 版系统提示词](prompts/v9.txt)：**AI 判断最小语义单元的绑定与适合断开的边界，本地程序计算最终页长。**

已实际调用 `https://api.deepseek.com/chat/completions`，模型为用户指定的 `deepseek-flash`。共保存 17 组、202 次用例请求的结果；另有一次固定文本连通性调用和一次模型列表查询。没有修改、审核、保存或发布线上文章。前述统计为提示词调研阶段的记录。文章编辑器现已接入 V9：UI → 业务服务 → 类型化 IPC → Rust → 已保存模型配置，详见项目 README 的“AI 文章分页助手”。素材导入已改为复用同一 V9 分页服务，旧正文整理和本地分页协议已移除。

## 样本与观察

首批按列表第 1、10、50 页抽取 24 篇、7 个分类、124 个正文页面；提示词冻结后另读取 6 篇作为新测试，合计 **30 篇、151 页**。这是一组有目的的小样本，娱乐与趣玩占比较高，不代表后台所有优质文章的总体分布。

字数按编辑器 DOM 可见文本的非空白 Unicode 字符统计，标点计入，图片、分页符和编辑器零宽占位符不计入。每篇解析出的页数均与列表“分页数”一致。浏览器已经对破损 HTML 做过归一化，因此这些统计描述编辑器当前呈现，不能据此断言服务端采用了某段具体算法。

| ------------- | ------------------: | ------------------: |
| 最短 / 最长页 |        70 / 1553 字 |        70 / 1553 字 |
| 第 25 百分位  |              152 字 |              163 字 |
| 中位数        |              228 字 |              258 字 |
| 第 75 百分位  |              501 字 |              501 字 |
| 第 90 百分位  |              694 字 |              694 字 |

首批样本中，55 页有 2 张图，34 页有 1 张图，30 页无图，另有 5 页含 3～4 张图。“1～2 张图一页”是常见表现，不能作为硬性分页配额。

观察到三类不同排法：

- **图多字少的短页**：如 `11658617`，1606 字、24 张图、12 页，单页 82～192 字；`11658031` 为 1149 字、15 张图、8 页。部分页面明显接近按图片数量切分。
- **以正文段落或小节为主的长页**：如 `11652758`，2245 字、4 页，单页 457～677 字；`11652698`，2769 字、3 页，单页 649～1143 字。科技、财经、军事样本也有大量无图长页。
- **短导语加首图，后续正文较长**：如 `11652693`，首页 128 字、末页 743 字；`11652745`，160 / 420 字。不能把这种个别排法推广为所有文章的固定首页规则。

“优质”标签也包含排版异常。例如 `11658652` 存在“但这个 / 理由……”和“他曾经 / 和……”这类句中断页，以及 `p>` 残片；`11658617` 多处在未完成的短句中切页；`11658627` 存在极短页和多处半句分页。不能把所有历史分页点直接当作训练答案。

完整样本的 ID、类别、标题、字数、图片数、逐页字数见 [实测记录](evaluation-results.json) 的 `articleSamples`。原始编辑器 HTML 和正文测试输入仅保存在本机调研目录 `C:/Users/uyoun/ego/cms-pagination-20261030/`，未加入 Git。

## 建议采用的分页规则

以下是根据观察形成的编辑策略，不是对 CMS 服务端算法的逆向结论：

1. 保留全部原文、原有格式、图片及顺序；分页结果只引用已有块编号。原始素材与分页草稿分开保存。
2. 标题和首段、图片和连续图注、完整引语、具体问题和回答、引出解释和具体解释、即时动作和直接结果组成不可拆的小单元。整场比赛或人物生涯不应被绑定成一个巨大单元。
3. 以约 **240 字/页**为短页初始目标，优先 160～320 字；正常多页尽量保持 100～400 字。全文不超过 280 字通常单页；完整不可拆单元自身超长可例外。
4. 图片数量属于软偏好。允许无图页、同页多图，不移动或复制图片来凑数。
5. 尾页不足 100 字时，重新平衡前后完整单元或合并最后两页。不得把剩余正文堆成超长末页。
6. 图注、来源和署名不能独立成页。纯图片文章保持原顺序、直接保留单页，不需要交给本提示词计算页数。
7. 非法编号、冲突语义建议、JSON 格式错误、截断、超时或不可安全映射的 HTML 均视为未完成；业务接入时应保留原排版并提示人工处理。

## 推荐提示词的输入与输出

系统消息使用 [prompts/v9.txt](prompts/v9.txt)，用户消息使用 JSON：

```json
{
  "title": "演示文章标题",
  "blocks": [
    {
      "id": "B1",
      "type": "text",
      "paragraph": 1,
      "text": "演示：记者提出了具体问题。",
      "chars": 13
    },
    {
      "id": "B2",
      "type": "text",
      "paragraph": 2,
      "text": "演示：负责人给出了相应答复。",
      "chars": 14
    },
    { "id": "B3", "type": "image", "paragraph": 3, "chars": 0 },
    {
      "id": "B4",
      "type": "caption",
      "paragraph": 4,
      "text": "演示现场图。",
      "chars": 6,
      "caption_of": "B3"
    }
  ]
}
```

`chars` 必须由调用方实际计算。图片使用占位符，不发送图片 URL 或图片内容。类型可为 `text`、`image`、`caption`、`heading`、`source`；`keep_with_next: true` 表示已经确认的紧邻绑定。

`caption_of` 应由可靠的 HTML 结构或人工标注确定；当前评估器要求图注紧随图片或同图连续图注，不会凭图片画面猜图注。长段可由程序在完整句末切成片段，但需要保留对应原 HTML 的安全位置，不能用模型返回的文字重建正文。畸形 HTML 的修复须作为独立步骤；本次测试输入移除了已确认的 `p>` / `>` 标签碎片，原始快照始终独立保留。

推荐模型输出：

```json
{ "bind_after": ["B1"], "prefer_after": ["B2", "B4"] }
```

- `bind_after` 是强约束：禁止在该块后分页。
- `prefer_after` 是软偏好：在长度相近的合法方案之间优先选择。
- 两个数组必须有序、唯一、引用已有编号，且互不重叠。末块编号作为无后续内容的建议忽略，不能形成文末空页。
- 本地程序合并显式绑定、图注和引语保护，再计算分页。评估脚本采用全篇动态规划，页长偏离 240 字的平方作为主要代价，短页或超长页有高代价，原段落末和 AI 建议是次要偏好。它是研究参考实现，与现有 Rust 的贪心 240/280/100 算法不完全相同。

最终分页点由本地代码产生，例如 `{"break_after":["B7","B15"]}`，再在安全的 HTML 块边界插入 `[!--empirenews.page--]`。模型不返回 HTML，不能借分页改写正文。

## 实际迭代结果

每次均调用真实 DeepSeek。不同阶段输入协议和本地算法也有调整，下表属于方案迭代，不能解释成仅改变提示词就取得的净收益。

| 版本 / 配置                      |            用例 | 通过全部自动检查 | 主要发现                                                  |
| -------------------------------- | --------------: | ---------------: | --------------------------------------------------------- |
| V1：直接返回分页点               |              10 |                7 | 长页、短尾页、语义绑定问题                                |
| V2：加入详细页长与图文规则       |              10 |                7 | 图片配额倾向反而制造短页                                  |
| V3：累计字数与全篇规划           |              10 |                9 | 长文返回文末编号，输出不合法                              |
| V4：合法候选与固定分页数量       |              10 |                9 | 长文仍有 29 字尾页和可拆长页                              |
| V5：本地初稿 + 非推理复核        |              14 |               11 | 3 个语义用例照抄初稿；纯字数初稿在 4 个语义用例均失败     |
| V6：逐点复核，默认 high 推理     |              14 |               13 | 长文耗尽 8192 token，`finish_reason=length`               |
| V6：low 推理，16384 token        |              14 |               13 | 相同长文触及 60 秒超时                                    |
| V7：只返回语义绑定与偏好         |              14 |               11 | 4 个语义用例都通过；真实文章的末块建议被过严格式检查拒绝  |
| V8：允许末块收束建议             |         14 + 20 |          14 + 19 | 首次留出集 19/20；1 篇仍将末块写入绑定数组                |
| **V9：统一忽略无后续的末块建议** | **14 + 20 + 6** |  **14 + 19 + 6** | **总计 39/40；新增 6 篇独立样本全过；1 篇冲突建议被拒绝** |

V9 使用 `thinking: {"type":"disabled"}`、`response_format: {"type":"json_object"}`、`max_tokens: 4096`。最终 40 个用例为 30 篇真实文章和 10 个明确标为演示的数据用例；其中 4 个演示用例包含独立标注的问答、动作结果、解释和引语边界，期望答案不发送给模型。

最终 V9 的 39 个有效响应延迟中位数 **921 ms**，第 95 百分位 **1361 ms**；40 次请求共返回计量输入 **93627 token**、输出 **2309 token**。这些是本次设备与服务时段的观测值。

未通过的真实文章为 `11652741`：模型在 `bind_after` 与 `prefer_after` 中同时引用多个相同编号，并把后半篇大量内容绑在一起。校验器拒绝了此输出，没有对其进行静默修补或伪装成功。最终 39/40 描述已定义的自动检查结果，不等于所有文章都已通过人工编辑验收。

纯本地字数初稿在相同 40 个用例中为 36/40，失败的是 4 个语义衔接用例。V9 修正了这些语义用例，同时引入 1 个已被拦截的无效模型结果。这正是需要模型输出校验与人工回退的原因。

全部轮次的提示词 SHA-256、编号输出、分页字数、错误、计量和延迟均保存在 [evaluation-results.json](evaluation-results.json)，有效输出还附有输入指纹。未保存密钥、请求头、原文输入或隐藏推理内容。早期预算耗尽和超时实验未能保留完整计量，不能用所有轮次的计量和推算精确总费用。

## 本地复现

离线检查不请求 AI：

```powershell
node --check scripts/pagination-eval.mjs
node --test scripts/pagination-eval.test.mjs
```

真实 API 复测需要显式运行下面的命令，并在当前进程中预先设置 `DEEPSEEK_API_KEY`。不要把密钥写入脚本、命令参数、`.env`、日志或仓库。

```powershell
node scripts/pagination-eval.mjs --fixtures docs/ai-pagination/demo-fixtures.json --prompt docs/ai-pagination/prompts/v9.txt --output .tools/pagination-eval --mode bindings --thinking disabled
```

此命令会产生真实 API 用量；脚本固定请求官方接口、禁止重定向、不自动重试，单请求超时 60 秒，默认并发 2。每轮最多 32 个用例。结果不满足检查时返回非零退出码。

真实文章测试输入在本机 `C:/Users/uyoun/ego/cms-pagination-20261030/fixtures-final.json`。该文件有 40 个用例，应通过 `--splits dev,edge,semantic` 与 `--splits validation,holdout` 分批运行。新增 6 篇另存于 `fixtures-fresh.json`。仓库中的 `demo-fixtures.json` 仅包含 10 个演示用例。

## 接入 PressDock 时的边界

编辑器分页助手与素材导入共用 Rust 的 V9 语义编号校验、AI 请求及全局页长规划。`ai_suggest_pagination` 额外返回 `breakAfter` 和本次实际使用的 `paginationOptions`，前端仅重建编辑器文档；导入通过 HTML 适配层重建正文，沿用 CMS 分页标记。两种适配器使用共同演示用例验证分块和分页点一致。

UI 经业务服务和类型化 IPC 访问 Rust，组件不直接调用外部接口。编辑器仍显式预览和应用；素材导入直接使用分页结果。原始素材始终独立保留。导入开关默认关闭，入队固定模板提示词、绑定模型 ID 及页长快照；配置缺失、无效响应、超时或不支持结构时保留原排版并警告继续导入，取消、会话失效与存储错误停止任务。模型密钥继续使用系统凭据库，不进入 localStorage。

## 业务接入验证

新增迁移将已有模板保留为标题用途，分页用途另有默认模板和页长参数。Rust 生产规划器仅返回分页编号；编辑器使用原节点切片重组，素材导入使用本地 HTML 节点重建。共同演示用例覆盖长段格式、图片及文字顺序保护；编辑器可整次撤销，语义非法响应直接拒绝。
