# Android 启动读取全局配置失败修复

日期：2026-11-07。设备：OnePlus 5 / Android 10，正式应用 `com.example.pressdock`。通过 USB adb 完成排查和操作，无需人工点击、登录或提供凭据。

## 已确认的原因

- 旧 APK 第 6 次冷启动复现：读取 1 次、成功 0 次、`SYNC_SERVER`，使用已有缓存。
- 手机端只读 HTTP 探针进一步捕获正式配置服务的 HTTP 503 / `CMS_TIMEOUT`，耗时 12,185 毫秒。凭据仅经内存及 adb stdin 传递；响应正文不落盘，记录仅包含 HTTP 状态、固定错误码和耗时。
- Worker 每次读取配置前，向固定 CMS CurrentUser 接口校验登录。原实现单次 10 秒超时、没有重试；瞬时上游超时使本次读取直接失败。
- 原客户端丢失具体 CMS 错误码，并且已有缓存时没有重试按钮。另一次真实冷启动还捕获到 `SYNC_NETWORK`；网络连接失败与 CMS 校验超时分别处理。

## 修复

1. Worker 仅对只读 CMS 鉴权的网络错误、超时和 HTTP 408/429/5xx 重试一次，每次最多 8 秒。总鉴权预算最多 16 秒，客户端仍只发起一次正常冷启动 bootstrap。重试不重复 D1 读取或配置写入。
2. HTTP 401/403、过期业务码、重定向和非法身份立即拒绝；两次临时错误均失败时不访问 D1，不使用旧鉴权结果放行。
3. 原生同步保留 CMS 错误码，日志仅记录固定错误码与 HTTP 状态，不记录令牌、响应正文或 AI 密钥。
4. 缓存提示增加“重试读取”，重试期间保留工作区和未保存输入；按钮防重复点击。正常冷启动、后台返回和网络恢复的读取时机保持原约定，新增读取由用户显式重试触发。
